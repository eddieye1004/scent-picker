## 零、两件必须先处理的基础问题

### B1 · 本地与远端 sha 分叉，下次 push 会被拒

| 项 | 内容 |
|---|---|
| 现象 | 本地 `main` = `a0a5f3b`，远端 `main` = `a99a353`，**内容相同但 sha 不同** |
| 原因 | `git push` 走 `github.com:443` 一直失败（`Recv failure: Connection was reset`，`curl https://github.com` 返回 000），改用 GitHub Git Data API 重建了提交。API 造的提交不在本地对象库里 |
| 后果 | `git push` 会报 non-fast-forward；`git status` 显示 `ahead 2` 是假的（那 2 个提交内容已在远端） |
| 修法 | 网络通时：`git fetch origin main` → `git reset --hard origin/main`（本地无独有内容，安全）。**不要用 `git push -f`**，那会把远端已有的东西推回旧状态 |
| 优先级 | **P0** —— 不修的话下一次提交后推不上去 |
