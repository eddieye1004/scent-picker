## 一、「公开域名是什么」

**你已经有，不用申请。**

```
https://eddieye1004.github.io/scent-picker/
```

GitHub Pages 对公开仓库免费提供 `用户名.github.io/仓库名/` 这个地址。
你的仓库 `eddieye1004/scent-picker` 是公开的、Pages 已开启，
所以这个 URL 现在就指向你的站点 —— 之前它跑的是 10-29 的旧版本，今天已更新到最新。

**它和「自己买域名」的区别**：

| | GitHub Pages 地址 | 自己买的域名（如 scentpicker.com） |
|---|---|---|
| 费用 | 0 | 约 ¥50–100/年 |
| 备案 | 不需要 | **国内服务器需要 ICP 备案**；指向 GitHub 则不需要 |
| 长度 | 长（37 字符） | 短、好记 |
| 联盟申请 | 能填，但阿里妈妈部分类目会要求 ICP | 更顺 |

**填进联盟后台时**：推广渠道选「网站」，网址填上面那个 GitHub Pages 地址。
如果平台要求备案号而你不想备案，改选「社群/自媒体」类目 —— 微博、小红书、
微信群都算，不需要域名。

## 二、「该怎么搞」—— 佣金接入的四步

完整指引在 **`docs/AFFILIATE-SETUP.md`**（含三家平台实测的注册入口与字段）。
这里只说顺序和你需要做的事：

| 步 | 谁做 | 做什么 | 耗时 |
|---|---|---|---|
| 1 | **你** | 注册京东联盟（有京东账号即可，扫码登录）→ 实名 → 申请推广位 | 约 15 分钟 + 等审核 1–3 天 |
| 2 | **你** | 同样注册淘宝联盟（要淘宝账号已实名 + 绑支付宝，部分类目要 ICP） | 约 20 分钟 + 审核 |
| 3 | **你** | 从两个后台各复制推广位 PID；再从「获取推广链接」复制几瓶的短链 | 每瓶 1 分钟 |
| 4 | **我** | 你把 PID 和短链发我，我写进配置并跑 `gen-affiliate-links.mjs` 生成表 | 约 10 分钟 |

**第 4 步之前页面已经能用**：现在是 `search` 档，每张卡有「在京东搜这一瓶 ↗」
和「在淘宝搜这一瓶 ↗」两个按钮，点了带你到对应平台的搜索结果页。
没有佣金，但也没有假承诺 —— 按钮文案写的是「搜」不是「买」。

**一个必须先接受的现实**：京东给的是**每瓶一条独立短链**（`u.jd.com/XXXX`），
不是可以套模板的参数化链接。所以「1228 瓶全部自动接上佣金」做不到 ——
只能一瓶一瓶拿链接，或者用开放平台 API（要 appKey/appSecret，
且仍需你知道每瓶在京东的 SKU 编号）。淘宝支持参数化转链，相对好办一些。

**这说明什么**：佣金这条链路的瓶颈从来不是代码，是**商品编号数据**。
知道香水叫什么，不等于知道它在京东/淘宝的商品 ID。

## 三、定时更新已经建好

`.github/workflows/update-data.yml`，每周一 03:17 UTC（北京 11:17）自动跑。

| 你关心的 | 实现 |
|---|---|
| 多久一次 | 每周一次（你选的） |
| 跑什么 | 取上游 → 重建数据 → 数据体检 → 四套 370 项测试 → **有变化才提交** |
| 失败会怎样 | 中止、不提交、写诊断摘要、GitHub 发失败通知邮件 |
| 能不能手动跑 | 能。仓库 → Actions →「每周更新香水库」→ Run workflow |
| 成本 | 0。公开仓库的 Actions 分钟数不限 |

**取数通道这次解决了**：之前一直卡在 `raw.githubusercontent.com` 是
`ECONNRESET`、抓取工具截断到 199KB。这次改用 GitHub 的 **blob API**
（`/repos/{owner}/{repo}/git/blobs/{sha}`，返回 base64 完整内容），
实测解码后 1,207,141 字节，与上游报告 size 一致、与本地文件逐字节相同。

所以「补 159 条」这件事也一并做完了：上游 1320 → 1479 行，入库 1228 → **1388 瓶**。

**它不会做什么**（几条边界，免得你等）：

- 不更新 taxonomy（24 类分类是人工判断，不能自动重算）
- 不生成佣金链接（需要你的账号）
- 不自动改 README 里的瓶数（那是给人读的句子，不是数字替换）

机制细节与手动操作见 **`docs/DATA-UPDATE.md`**。

## 四、今天顺手修掉的两个真问题

### 「最匹配」和「初步匹配」同时出现在一张卡上

线上截图发现的：第 1 张卡左边标「最匹配」、右边标「初步匹配」——
一句话说"它最合适"，另一句说"我们算不准"，互相拆台。
改成：没有百分比时徽标说「**原始分最高**」（这是事实，不需要百分比支撑）。

**为什么这条值得单独说**：那个断言之前**从未触发过** ——
主流程跑出来的数据恰好三瓶并列，徽标数是 0，所以
`if (badges.length)` 那段代码一直没执行。抽成纯函数后才真正钉住。

### 断言钉死了一个会正常变化的数字

`qa-checks.mjs` 原本写 `upstreamLines === 1320`。它守的不是"必须 1320"，
而是"原件还在"。上游一长到 1479 这条就红 —— 门变成了"守我们上次下载了多少行"。
改成守"原件行数 ≥ 输出条数"与"meta.count 与输出一致"。

这是同类错误在本项目的**第三次**（前两次：把 `--accent` 绑死一个色值、
深色块被浅色对比度断言误判）。判断标准：**门守着一个会正常演进的量，
就会在正常演进时误报。**
