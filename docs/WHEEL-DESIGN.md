# 香气轮盘改版设计

> 依据：抖音「小羊寻香」视频《我发现了找到本命香最靠谱的办法》（aweme_id `7648618260774046982`，4 分 8 秒，抓取日 2026-10-28，逐帧读取画面内嵌字幕后整理）。
> 数据约束：本文写作时 `data/perfumes.json` 是 **200 瓶**；执行阶段按 D16 扩到 **400 瓶**，抽样改为「家族 + 子家族」双配额，32 个子家族最薄 7 瓶。本文第 1.2 节的实测数字仍是 200 瓶时的，保留是为了说明「当时为什么要扩」，扩后的新数字见 D16。

---

## 一、分类依据提取

### 1.1 视频给出的结构（原样照抄，不加工）

视频用 **4 个大组 → 13 个小组** 的两级结构：

| 大组 | 小组 | 视频原话（画面字幕） |
|---|---|---|
| 清新调 fresh | 水生、绿色、芳香、柑橘 | 「它也是接受度最高的」／「四个分支」 |
| 木质调 woody | 干燥木质、木质（纯粹木质）、苔藓木质 | 「追求那种极致干爽」／「营造出扎实+温暖的安全感」 |
| 琥珀调 amber | 柔和琥珀、琥珀、木质琥珀 | 「不是指琥珀的味道」／「金黄+浓稠的温暖感」／「让温暖感呢」 |
| 花香调 floral | 果香、花香、柔和花香 | 「水蜜桃荔枝等水果的氛围」／「栀子花」／「营造出一种高级的脂粉感」 |

视频的关键主张有三条，直接决定了改版方向：

1. **轮盘是「建立坐标」的工具**，不是推荐器。原话概括：用它弄清自己的**舒适区、雷区、未知区**。
2. **先试香再买**。视频结语自己就在劝退盲目消费。
3. **判断依据是「气味」而不是「感受」**。全片讲的是水生/苔藓/橡木苔/广藿香这类能对上具体物质的东西。

> 这正是你提出的「禁止清冷/慵懒/神秘」的理由：视频本身就没用感受词，它用**香材**建立参照系。感受词无法被验证，香材可以——你闻到橡木苔就知道是不是这一格。

### 1.2 现有数据能不能支撑 13 个分类（实测，不是估算）

拿 200 瓶实测每类能命中多少瓶（当时的库容；扩到 400 后全部子家族 >= 7 瓶）。判定用 `families` 权重 ≥ 0.3（主导或并列主导）：

| 候选家族 | 可推荐池 | 结论 |
|---|---|---|
| 花香 floral | 120 瓶 | 撑得住 |
| 木质 woody | 84 瓶 | 撑得住 |
| 芳香/馥奇 aromatic | 62 瓶 | 撑得住，但与清新高度重叠 |
| 琥珀 amber | 58 瓶 | 撑得住 |
| 柑橘 citrus | 46 瓶 | 撑得住 |
| 美食 gourmand | 42 瓶 | 撑得住 |
| **果香 fruity** | **9 瓶** | **撑不住** |

果香只有 9 瓶：要求「≥2 个果香材 且 floral 权重 < 0.5」才判为果香主导。原因是源站把桃/荔枝多数归进了「花香」的子类（`fruity-floral`），数据层面没有独立的果香家族键。

**取舍一：果香不单独设扇区，降级为花香的第二层子类。** 理由：第一层点进去只有 9 瓶，用户会觉得「选了半天就这几个」，比不给还差。视频把果香放在花香组下——这条它和数据的判断是一致的。

### 1.3 最终第一层：6 个家族（在你要求的 6–8 区间内取少）

| 扇区 | 中文 | 典型香材（数据实测高频，非杜撰） | 一句话描述 |
|---|---|---|---|
| 1 | 柑橘调 Citrus | 佛手柑 15、柠檬 13、橘子 7、橙 7 | 刚剥开的果皮。明亮、干净，最不容易踩雷，也最不持久 |
| 2 | 花香调 Floral | 玫瑰 37、茉莉 29、鸢尾 12、橙花 | 从一朵花到一整束花。范围最广，最容易买错方向 |
| 3 | 木质调 Woody | 雪松 22、广藿香 22、香根草 21、檀木 15 | 干、稳、有骨架。留香最久，味道最深 |
| 4 | 琥珀调 Amber | 香草 12、胡椒 12、劳丹脂 9、安息香 | **不是琥珀本身的味道**，是一组暖、稠、有分量的树脂与香草 |
| 5 | 清新调 Fresh | 佛手柑 15、薰衣草 9、杜松 8、薄荷 6 | 水、空气、草地。接受度最高，也最容易晕香 |
| 6 | 美食调 Gourmand | 零陵香豆 12、香草 10、天芥菜 4、果仁糖 3 | 像甜点。喜欢的人极喜欢，讨厌的人觉得像糖浆 |

数字来源：`data/perfumes.json` 中该家族主导（`families` 权重 top-1）的瓶子里，各香材出现次数。脚本 `_probe-notes.cjs`。

**取舍二：扇区里写「典型香材」而不是写形容词。** 你要求每扇区标注典型香材，这是对的：香材名是唯一能让新手「对上号」的东西。写「温暖」他不知道暖到什么程度，写「香草、安息香、劳丹脂」他能去闻。

**取舍三：琥珀调的描述必须点破「不是琥珀的味道」。** 视频专门讲了一句「不是指琥珀的味道」——这是新手最大的误解源（以为是一块石头的味道）。保留这句话的意图，用「一组暖、稠、有分量的树脂与香草」实现。

## 二、轮盘层级设计

### 2.1 第一层：6 扇区家族盘

- **几何**：沿用现有 `buildDisc()`，6 扇区，外径 230 / 内径 104（480 坐标系）。
- **每扇区三行字**：家族中文名 / 英文名 / 典型香材（逗号分隔，最多 3 个，超长省略）。
- **盘心**：空态显示「先选一个气味家族」；指针悬停/聚焦某扇区时，盘心换成该家族的 `oneLine` 加全部典型香材。
- **选中反馈**：扇形填色从 `--bg-2` 提到 `--accent` 低透明度，描边换成 `--accent`，盘心文字固定为该家族，下方出现「下一步 →」。

**取舍四：第一层只给 6 个，不给 7–8 个。** 果香撑不住（9 瓶）；皮革只有 19 瓶且分散在琥珀的子类里，独立成区反而误导。6 个扇区每块 60°，是圆盘上最舒服的角度——超过 8 个，扇区会窄到标签放不下（实测 8 扇区时每块只有 45°，中文名 + 香材三行挤不下）。

### 2.2 第二层：同一圆盘换成该家族的子类

- **几何不变**，扇区数量换成该家族的子家族数（3–6 个）。视觉上像圆盘「翻了一面」，用户不会觉得换了页面。
- **每扇区内容**：子类中文名 / 该子类下的代表香材（1–2 个）/ 命中瓶数（可选，帮助判断稀有度）。
- **盘心**：显示「已选：花香调 · 玫瑰」，并提供「← 换个家族」回退。

实测每个子家族能命中多少瓶（`_probe-sub.cjs`，判定按香材词匹配，非裸子串）：

| 家族 | 可用子类（瓶中数） | 必须剔除 |
|---|---|---|
| 柑橘 | 古龙水型 36、芳香柑橘 78、柑橘花香 25、青绿柑橘 18 | 无 |
| 花香 | 白花 62、玫瑰 60、粉感花香 45、黄花 13、绿叶花香 11、果香花香 10 | 单一花（0） |
| 木质 | 苔藓木质 83、檀木 59、干燥木质 57、香根草 45、乌木 10 | 芳香木质（0） |
| 琥珀 | 香草琥珀 72、辛香琥珀 25、皮革 19、树脂 12、焚香 11 | 无 |
| 清新 | 水生 91、馥奇 34、海洋 11、茶香 6、绿意 4 | 茶香、绿意偏薄 |
| 美食 | 香草甜 95、坚果杏仁 9、咖啡可可 4、酒香 3 | 果味甜（0）、咖啡可可、酒香 |

**取舍五：0 瓶的子类必须删，不能留着占扇区。** 单一花、芳香木质、果味甜三个子类在 `noteIndex` 里没有任何香材挂靠（`香材 0 个`），点进去是空的。这三条要么补香材映射，要么从轮盘移除——**不移除就是死选项**，和上一版修掉的死 chip 是同一个错误。

**取舍六：第二层给 3–6 个扇区，不照搬视频的 3 个/4 个。** 视频的 13 分类是「教学分类」，每类都讲；本项目要在 200 瓶里真能筛出东西，所以子类数量跟着「有货」走：花香 6 个、木质 5 个、琥珀 5 个、柑橘 4 个、清新 5 个、美食 4 个（剔薄后）。

### 2.3 第三层起：场景与浓度后置

按你的要求，场合、浓度、想如何展现自己全部推到第三轮：

| 轮次 | 问什么 | 为什么放这里 |
|---|---|---|
| 3 | 主要在哪用？（上班上课 / 约会 / 日常居家 / 正式场合 / 运动户外） | 前面已锁定「闻起来像什么」，这里只影响**浓度上限与扩散**，不影响家族选择 |
| 4 | 希望多浓？（1–5 滑杆） | 同上。且滑杆比圆盘更适合表达连续量 |
| 5 | 有没有受不了的味道？（可跳过） | 排除项放最后：先让用户建立正向偏好，再让他划掉雷区。反过来会让人一开始就防御 |

**取舍七：不把场合混进第二层。** 场合是「使用约束」，家族是「气味偏好」，两者正交。混在一层会让用户以为「选约会就会变成花香」。

## 三、交互路径

### 3.1 主路径

```
[首屏] 6 扇区家族盘
   ↓ 点选（或方向键 + Enter）
[第 2 屏] 同盘翻面 → 该家族 3–6 个子类
   ↓ 点选
[第 3 屏] 场合盘（5 扇区，同一组件）
   ↓ 点选
[第 4 屏] 浓度滑杆
   ↓ 拖动 + 下一步
[第 5 屏] 香材勾选（喜欢 / 受不了两栏，可跳过）
   ↓
[结果页] 3 瓶，每瓶香调金字塔 + 引用所选家族/香材的理由
```

### 3.2 回退与重开（你明确要求的）

| 操作 | 触发 | 行为 |
|---|---|---|
| 回退一格 | 每屏底部「← 上一步」 | 退回前一屏，**保留已答内容**并显示为已选中 |
| 换家族 | 第 2 屏盘心「← 换个家族」 | 直接回第 1 屏，清空第二层选择但**保留第一层高亮** |
| 从中心重开 | 盘心常驻「重选」按钮（`.disc-hub` 内的次要按钮） | 清空全部答案，回第 1 屏空态 |
| 全局重开 | 结果页「重新开始」 | 同上，另加滚回顶部 |

**取舍八：回退保留已答内容，不重置。** 新手最常见的动作是「退回去看看刚才选的是哪个」，重置会让他重新选一遍，多花 20 秒。宁可多写一个显式的「重选」按钮，也不要让回退带破坏性。

### 3.3 移动端约束（硬指标，进测试断言）

| 指标 | 要求 | 当前实现是否达标 |
|---|---|---|
| 触控目标 | ≥ 56px（你要求，高于 WCAG 的 44） | 实测扇区 56×59.2 ✓ |
| 横向滚动 | 无 | 实测 `bodyScrollW 1424 < winW 1439` ✓ |
| 首屏可见 | 圆盘完整在首屏内，不需滚动 | 圆盘 `560×560`，在 1280×1100 视口内 y 起点 314 → 底 874 ✓；**手机上需复核**（见下） |
| 交互方式 | 点选为主，不做长表单 | 前 3 屏全是点选，第 4 屏滑杆，第 5 屏点选 |

**手机首屏：已实测并已修复（D19）。** 推算阶段判断 iPhone SE 会溢出，实测确认了——原实现圆盘 345.2px，加上头部与提问区共占 675.6px，**超出 667px 视口 8.6px**。修复是把 `.disc` 宽度从 `min(88vw, var(--discw))` 改成 `min(88vw, 62vh, var(--discw))`，并压掉 60px 竖向留白。修复后五档实测（390×844 / 375×667 / 360×740 / 430×932 / 768×1024）全部首屏可见、无横向滚动、扇区 >= 56px。

## 四、结果呈现

### 4.1 每瓶卡片结构

```
品牌 · 名称                            浓度标签
─────────────────────────────────────────
香调金字塔
  前调  佛手柑 / 柠檬 / 橙花
  中调  玫瑰 / 茉莉 / 鸢尾
  后调  香草 / 香根草 / 麝香
─────────────────────────────────────────
为什么是这瓶（3 条，必须引用你所选的内容）
  · 你选了「花香调 · 玫瑰」，它的主体正是玫瑰 + 茉莉
  · 含你点名的 香草
  · 选了「约会」+ 浓度 4，它的扩散 0.68 落在这个区间
─────────────────────────────────────────
数据来源 ↗
```

### 4.2 理由的硬约束

- **必须至少一条引用第一层家族名**（如「花香调」）——这是你要求的「理由需引用用户选中的气味家族或香材」。
- **必须至少一条引用第二层子类或香材名**（如「玫瑰」）。
- 条数 2–3 条，不堆砌；超出则按「家族 > 子类/香材 > 场景 > 浓度」优先级截断。

**取舍九：理由不写「适合你」这类空话，写「你的哪个选择对上了这瓶的哪个部分」。** 前者无法验证，后者用户能自己核对——他点了玫瑰，卡片写「它的中调是玫瑰和茉莉」，对得上就是信任，对不上就是 bug。

## 五、要改的数据（实测出的 3 个死子类）

`data/taxonomy.json` 里有三个子家族的 `noteIndex` 挂靠为空，必须处理：

| 子家族 | id | 现状 | 处理 |
|---|---|---|---|
| 单一花 | `soliflore` | 0 个香材 | 补香材（如 rose 单用、jasmine 单用）或移除 |
| 芳香木质 | `aromatic-woody` | 0 个香材 | 补香材（lavender / rosemary / sage）或移除 |
| 果味甜 | `fruity-gourmand` | 0 个香材 | 补香材（peach / praline）或移除 |

另有两个偏薄：`茶香` 6 瓶、`绿意` 4 瓶。二次判断是「补香材提高命中」还是「并入其他子类」。
