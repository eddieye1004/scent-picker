# 24 枚 SVG 图标的视觉设计经验（可复用）

> 来源：2026-10-31 → 2026-11-08 的完整图标任务，约 60 轮返工。
> 只写**被实测否决过、又验证通过**的结论；每条都注明当时的读法错误。
> 适用对象：24×24 画布上、在小尺寸（24–88px）下必须被正确识别的**物体类**图标。

---

## 零、先定一件事：你的画布是几像素

这一条放在最前面，因为它是本任务**代价最大的一次误判**。

- 按 24px 校间距，是前 20 余版失败的第一原因。
- 真实渲染尺寸实测：`1440` 视口下盘心 **88×88**，`390` 视口下 **36×36**。
- 换算：`viewBox="0 0 24 24"` 时，**1 单位 = 3.67px（88px）/ 1.5px（36px）**。

由此推出三条硬阈值：

| 量 | 判据 | 理由 |
|---|---|---|
| 最小可见缝 | **≥ 2.5 单位** | 36px 下 2.5u ≈ 3.75px；再细会被抗锯齿抹平 |
| 内部纹理描边 | 0.22–0.50 | >0.50 在 36px 下变成实心块；<0.22 完全消失 |
| 主轮廓描边 | 0.85–1.00 | 低于 0.85 在 88px 下发灰；高于 1.00 在 36px 下吃掉内部结构 |

**先量渲染尺寸，再动笔。** 不要用设计软件的"看起来差不多"代替实测。

## 一、读法优先：图标不是缩小版插画

一个图标是否成功，判据只有一条：**在 36px 下，一个没见过这枚图的人能否用一句话说出它是什么，且那句话是你想的那句**。

### 1.1 形状的"读法陷阱"对照表

这些都是被用户当场否决过的（"这是什么？"也算否决）：

| 你想画 | 画法 | 实际被读成 | 修法 |
|---|---|---|---|
| 玫瑰 | 三层同心圆 | **靶心** | 花瓣必须有缺口与错位，三层不能同心 |
| 玫瑰 | 扇贝形外缘 | **云朵 / 胡子** | 花瓣顶端要收尖，锯齿要少 |
| 乌木 | 闭合同心环 | **靶心** | — |
| 乌木 | 螺旋 | **蜗牛** | — |
| 乌木 | 实心挖空 | **汉堡** | — |
| 乌木 | 平行断纹 | **C 字** | 纹理要顺长轴、连续、低对比 |
| 香根草 | 5 片拱叶 + 叶鞘 | **芦荟 / 多肉** | 叶宽必须 ≤0.30，叶尖要真收尖 |
| 香根草 | 宽叶放射 9 片 | **棕榈 / 龙舌兰** | 与叶数、弯曲无关，只与叶宽有关 |
| 香根草 | 叶尖下垂到基部以下 | **章鱼 / 蜘蛛** | 喷泉形会破坏 bbox 纵横比 |
| 檀木 | 竖直/双向/中央放射 | **扫把 / 耙子 / 蜘蛛** | — |
| 檀木 | 几片等距垂线 | **栅栏 / 蘑菇** | — |
| 木质 | 矮方木 + 苔团 | **花盆** | — |
| 木质 | 端面圆盘 + 放射裂 | **轮毂** | 年轮必须是偏心的椭圆环 |
| 皮革 | 圆角方块 + 虚线边框 | **银行卡** | — |
| 树脂 | 三小滴 | **碎块** | — |
| 香草荚 | 直梭形 | **刀片 / 叶子** | 必须画成弯曲月牙 |
| 香草荚 | 深色直板 | **记号笔 / 筷子** | — |
| 香草奶油 | 多圈同心螺旋 | **靶心 / 年轮 / 涟漪** | 只许单圈、略收、不同心 |
| 绿意 | 窄长尖叶 | **竹叶 / 草** | 叶要用宽椭圆，脉从椭圆参数方程取点 |
| 水生 | 三道同心波 | **wifi 信号** | 波纹必须与水珠轴线对称 |
| 馥奇 | 4 对侧叶同点起笔 | **深色楔形 + 牛角** | 每对叶要错开基点 |
| 香根草 | 一束草茎等距并排 | **梳齿 / 流苏 / 扫把** | 见 §4.2，间距有下限也有上限 |

### 1.2 三条"必然读错"的组合（无条件避开）

1. **圆形物体上散布 ≥2 个小圆点 → 必然读成眼睛。**
   实测三次：树脂凹坑（暗心 + 环绕亮弧）、皮革穿带孔（浅底 + 深芯 + 亮弧）、香草荚上的籽。前者改"实心暗窝 + 单向短高光"，后两者**整段删除**。
   例外：两点的半径差 ≥2 倍时不会读成眼睛（树脂气泡 r 0.235 / 0.115 / 0.075 通过）。

2. **小尺度（≤0.5 单位）的细碎线条在 88px 以下全部合并。**
   任何"分组线 / 年轮 / 刻槽"都会读成十字、加号或一团墨。断面上的 3 条分组线就被读成"加号"。

3. **不与主形同心的线段 → 读成螺旋。** 这条是 `PLATE_MOTIFS` 时代就写进代码注释的约束，本轮再次印证。

### 1.3 一张图只允许一个"语言体系"

- 其余 23 枚都是**物体**语言（木段 / 琥珀块 / 皮革 / 瓶子 / 花）；香根草一直画成"一丛绿色细条"，就永远低一档。
- 修法不是调曲率，而是给它**体积**：捆绳 + 束身 + 断口，让它变成"一捆草"这个物体。
- 同理：茶香不许出现"白色宽带中脉"（在 192px 下读成**拉链**）；裂叶的叶脉不许用直线 `L` 而顶叶用曲线 `Q` —— **同一枚内笔触风格必须统一**。

## 二、几何：让形状自己收尖

### 2.1 叶尖必须由轮廓收敛产生

- ❌ `halfW = wid * sin(π·t)^p` → 叶尖永远是**圆头**，`p` 取任何值都不行。这是 12 版香根草全部失败的表面原因。
- ✅ `halfW` 末端**强行归零**：`down = 1 - (t - t0)/(1 - t0)`，线性到 0。
- ✅ 更稳的是「先平截再圆角收口」：`hw(t)` 在 `t≤0.16` 时 `wid*(0.55+0.45*(t/0.16)^0.7)`，中段满宽，`t>0.48` 后 `wid*(1-((t-0.48)/0.52)^1.8)`，叶基用**两段圆弧**收口（`w0 = hw(0)*1.10`）。
  **为什么**：收到 0 会形成"针尾 / 根刺"（K/L 候选全因此废）；平截 + 圆角才像被折断的草茎。

### 2.2 Catmull-Rom 在非闭合路径上必须 clamp 索引

这是 12 版香根草**真正的**根因，值得单列：

```python
def cr(pts, close):
    n = len(pts)
    def at(i):
        if close:
            return pts[i % n]
        return pts[max(0, min(n - 1, i))]   # ← 关键
```

原写法 `pts[(i + n) % n]` 在末段 `i=n` 时回绕到**第 2 个点**，导致每条叶缘末端向外过度凸出 —— 叶尖永远是圆的。修后 `autofit` 的 `k` 从 0.81–0.84 变成 **1.000**（几何本身不再溢出安全框）。

**推论**：如果 autofit 的 k 明显小于 1，先怀疑生成几何本身有异常凸出，而不是"压缩得不够"。

### 2.3 闭合轮廓必须一次闭合，不要拼接

- ❌ `crPath(right) + crPath2(left[::-1]) + 'Z'` → 叶基留一个凸起**小尾巴**。
- ✅ 拼成一个 `loop` 再闭合：`loop = right + [right[-1]] + left[-2:0:-1] + [left[0]]`，`cr_path(loop, True)`。
  **为什么**：在尖端插重复点使切线归零，端点才不回勾。

### 2.4 叶片用椭圆参数方程算脉端点，保证永不越界

```python
pt(th, r) = [CX + RX*r*cos(th), CY + RY*r*sin(th)]
```
- 侧脉终点取 `r = 0.86`（不是 0.90）——要留出主轮廓描边半宽 `0.92/2 = 0.46`，否则脉尖冲出叶缘。
- 主脉暗边**不要整条等偏移**（会形成"三线并行"）：偏 0.46、只走中段、首尾各收 1.15 / 1.30、`opacity 0.26`。

## 三、材质：让平面看起来有体积

### 3.1 圆柱（木段 / 檀木）：解析式参数化，不要手画

```python
Q(c, R, theta) = c + n*R*sin(t) + u*E*R*cos(t)
```
- `u` = 轴向单位向量，`n = (-uy, ux)` = 法向。
- `E` = 端面压缩比（透视扁度）。**实测 E < 0.55 会被读成"月牙"**，0.40/0.36 全废，0.76–0.80 可用。
- 半径太小会读成"两个饼夹一段"：`R ≈ 2.4–3.9` 对应 `长 12–14`，`R=3.42 + 长 12` 就废了。
- **全程不用 `A` 命令**：`autofit` 的 `scale_d()` 只吃单段 arc，多段连写会 `ValueError: not enough values to unpack (expected 7, got 1)`。一律用三次贝塞尔（`K = 0.5522847498`）。

### 3.2 受光侧搞反是高频 bug

`n = (-uy, ux)` 在斜放柱体上指向**下方**。所以：
- 受光必须在 **`-n` 侧**，背光在 **`+n` 侧**。
- 全部写成 `+n` 受光 → 木头像被从下方打光，整体发灰。
- 检查法：算一次 `off(P, -R*0.72, t)` 的 y 值，看它是不是比中心线更高。

### 3.3 高光/背光弧必须沿柱面采样

```python
shade_arc(n, R0, R1, frac, t0=0.13, t1=0.87, steps=18)
```
- 硬写二次贝塞尔控制点 → 弧冲出端帽，露出白色月牙 / V 形缺口。
- 端点收在 `t = 0.13 / 0.87`（端帽内侧），不要 1.0。
- 断面上的"白高光弧"最终**整段删除** —— 半轴 `E*R*0.52` 配 `-n*0.92` 组合必然越界；断面靠年轮 + 髓裂已经足够。

### 3.4 表面纹理：连续长线 + 低对比 = 材质；分段 + 高对比 = 贴条

木质纹理试过 5 种画法，只有最后一种通过：

| 版本 | 画法 | 读成 |
|---|---|---|
| v1 | 4 条贯穿全长的平行线 | **卷起的纸 / 竹简** |
| v2 | 每条断成 2 段、相位交错 | **胶带贴条** |
| v3 | 断成 3 段 + 明暗跳变 | **碎块** |
| v4 | 5 条连续长弧 + 低对比 + 疏密不均 | ✅ 木纹 |

定稿参数：`#B79F77` / `#AD956D`，`opacity 0.26–0.34`，`f = -0.64 / -0.30 / 0.02 / 0.34 / 0.64`，`w` 交替 ±0.16–0.26，`t ∈ [0.06, 0.94]`（两端由断面椭圆盖住）。

### 3.5 纹理半宽必须换算成"画布绝对宽度 ÷ 当地半径"

```python
def groove(c, frac, t0, t1, halfw, taper=0.20, steps=20):
    R = lerp(c.R0, c.R1, t)
    w = halfw * k / R          # ← halfw 是画布单位；除以当地半径才是 frac 偏移
```
- 直接给 frac 偏移 → 透视收缩端被压成**楔形**，整个图标读成"爪痕 / 羽毛"。
- 两端必须 **taper**（`k = 0.20 + 0.80*(u/taper)`）：等宽走到端头会留一道齐刷刷的竖切线，读成"贴了纸条"。

### 3.6 "纹理乱"的三个具体成因（可量化）

用户说"纹理是乱的"时，实际指的是：

1. 每条纹的**起止位置不同**（参差不齐）
2. **粗细与透明度随机跳变**
3. 条带**有楔形**

修法：**统一起止 + 等距 + 只靠粗细/浓淡分主次**。
- 檀木：6 主（`sw 0.058`）+ 6 次（`sw 0.032`），`for i in range(6): (-0.775 + 0.310*i, …)`
- 木质：5 主（`sw 0.085`）+ 4 次（`sw 0.042`），`for i in range(5): (-0.80 + 0.400*i, …)`

### 3.7 各类材质的"正确语言"

| 材质 | 主轮廓 | 表面 | 端面 / 断口 |
|---|---|---|---|
| 木质（带皮原木） | 深褐渐变 `#C6A377→#A9855A→#6E4C26`，描边 0.58 | 树皮 5 主 + 4 次深沟，**走下缘轮廓外**（3 层叠加 `#3E2410/#573418/#241408`） | 浅色新断面 + 深色树皮环 |
| 檀木（去皮心材） | 暖浅 `#F6DDB2→#E2B77E→#B47C42`，描边 0.56 | 8–12 条细顺纹 `#B07A3E` | 深色心材芯 + 偏心年轮 + 髓心 |
| 乌木 | 近黑 `#4A3524→#0D0805`，**`stroke="none"`** | 顺纹比底色**亮**（暗线读成"薄板叠起来"） | 右侧弧形锯切面，缝只走中段 |
| 树脂 | 降饱和金 `#FBE3A8→#8A561A`，描边 0.46 | 5 条流线各画两笔（亮主 + 偏移 0.10 的暗边） | 左上树皮块（树脂从它下面渗出） |
| 皮革 | 描边 0.96 | 6 条短折痕，高光按**离受光上缘距离递减** | 卷边 + 针脚（孔一律不画） |

**三种木材必须靠三条同时拉开**：色温（暖浅 vs 深褐 vs 近黑）、侧壁纹理（顺直细丝 vs 横向沟裂 vs 长轴亮丝）、端面（心材芯 vs 树皮环 vs 锯切面）。只改颜色一定会撞车。

### 3.8 受光强度要按"离光源距离"递减

皮革 `LIT = [0.34, 0.30, 0.20, 0.14, 0.05, 0.26]`：

```python
if LIT[i] > 0.08:                       # 太弱的折痕只留暗线
    transform = translate(-LIT[i]*0.26, -LIT[i])
    sw  = 0.14 + LIT[i]*0.32
    op  = 0.14 + LIT[i]*0.60
```
- 6 条折痕全部同向、同强 → 读成"揉皱的纸"。
- 第 5 条 `LIT 0.05` 只留暗线 —— 这才是"下半区受光弱"的正确表达。

## 四、构图与视觉重量

### 4.1 重心必须在 12 附近，且**改形态不是改描边**

- 用户两次报"视觉重心偏上"：檀木 / 木质 cy **8.99 → 11.91**，茶香顶叶收窄上移、下两叶加宽加长（质心 10.84 → 11.67）。
- 修法只有两条：**整体平移**（`Cyl` 的 `y` 全部 +2.40）或**改各部件配比**（下叶加宽）。
- ❌ 绝不靠加粗线条"压住"重心。用户原话：「我说的细长是修改形态不是加粗线条」。
- **实测容差**：`cy ∈ [11.5, 12.5]` 视觉居中；`cy < 10` 明显偏上（rose 9.30、sandalwood 9.07 都被指出过）；`cy > 14` 偏下（fruity-gourmand 14.27）。

### 4.2 一束细物的间距有下限也有上限

草茎并排的实测区间：

| 间距净空 | 结果 |
|---|---|
| `0.46 − 0.13×2 = 0.20` | 被描边填满 → **实心块** |
| `0.60`、描边 0.075 | 仍实心 |
| 每叶各自描边 | 描边互吃 → **一整块实心绿** |
| **间距 > 2×描边宽 + 0.25** | 才不糊；但间距一大又变**扫把** |

结论：24 单位画布上草束类**没有可行的纯并排区间**。必须换表达——
- 要么**加物体感**（捆绳 + 束身 + 断口，让它变成"一捆"而不是"一丛"）；
- 要么在**束内留白**（先铺深色底，再用亮色画出每根茎的亮边）。

### 4.3 安全框

- 设计口径 `3.30–20.70`；归一工具口径 `3.70–20.30`（更严，留出描边余量）。
- 越界**必须靠几何收，不靠缩**：`safety.py` 逐图元写 `transform="translate(dx dy) scale(k)"` 并同步 `stroke-width /= k` 保持视觉线宽，最多迭代 5 次。
- `transform` 列表是**矩阵左乘，最右边先作用** → 遍历必须 `reversed()`。正序会把注入的 `scale(k)` 当成最先应用，收敛全错。

### 4.4 CSS 层与 SVG 层的分工

上色 SVG 的 590 个图元**全都没写 `stroke`**，直接塞进页面会继承 `.plate-svg { stroke: var(--ink-3) }` 被描成灰边、选中态再被 `--blue` 描成蓝边（檀木端面那圈蓝环就是这么来的）。必须在 CSS 断掉继承：

```css
.wheel .plate-svg.is-art { fill: initial; stroke: none; stroke-width: 0; }
.wheel .plate-svg.is-art, .wheel .disc-hub.is-picked .plate-svg.is-art { stroke: none; }
```

**同理反推**：给 SVG 写内联 `fill` 时，也要假设外层可能带 `fill:none` —— 显式压过去，不要靠继承。

## 五、小尺寸可读性的验收方法

`bbox / ink% / 描边档` 这些数值**只能发现越界与重量问题，发现不了读法问题**。必须两条腿：

| 手段 | 能发现 | 不能发现 |
|---|---|---|
| 解析式审计（bbox / sw / 体积 / 图元数） | 越界、描边越级、体积超限、图元爆炸 | 一切"读成别的东西" |
| 单枚 860px 白底渲染 | **读法错误**（唯一有效手段） | 越界（看不出 0.1 单位） |
| 多档尺寸表（192 / 88 / 36 / 24） | 36px 下是否糊、缝是否还在 | 大尺寸下的细节错误 |
| 真实页面逐格截图 | 继承样式、闪帧、跳版 | — |

**一条铁律**：断言抓不到"两状态并排对比"类缺陷（kicker 消失、盘底跳色、hub-skip 露出，三处都是靠截图才发现的）。

## 六、工程纪律（这些坑代价最大）

1. **改含中文的文本文件，禁用 PowerShell `Set-Content`。**
   它会按 GBK 读入再以 UTF-8 写回，整篇中文变乱码（`index.html` 3753 B → 2130 B，逆转尝试 cp936/gb18030/cp932/cp1252/latin-1 全部失败，只能从备份恢复 + 手写重建）。
   用 `write` 工具或 Python `io.open(..., encoding='utf-8')`。

2. **备份走 `MANIFEST.sha256` + 时间戳目录，不靠 git。**
   本项目 `scent-picker/` 在 `.gitignore:22` 里（`/scent-picker/`），git 里 0 个跟踪文件。所有回滚点都是手工目录 + 逐文件 SHA256。

3. **删除前必须"逐文件 SHA256 校验通过才删"。**
   `shots/` 清理：1403 文件 / 137 MB 备份到 `scent-shots-bak-20261108/`，`MANIFEST.sha256` 1402 行全部核对后才执行删除。

4. **`autofit` 的描边归一必须设上限。**
   原逻辑 `ratio = 0.92 / (swmax*k)` 无上限：草束类最大描边本来只有 0.16，被放大 **5.75 倍**成 0.92 → 整束糊成实心块。加 `ratio = min(ratio, 1.60)`。
   并且 `ratio` 下限写死 1.0 会让"想收细"的 `--out=` 完全失效 —— 要细必须生成器直接写低 `sw`。

5. **`<ellipse transform="rotate(a cx cy)">` 在归一化时会出错。**
   工具会把旋转中心与 `cx/cy` 分开缩放，端面年轮整体偏移（实测椭圆落在 `cx=6.81` 而年轮圆心在 `(6.8, 12.31)`）。一律改用参数化 path 画椭圆。

6. **"抽最大轮廓"不能生成线稿。**
   用 RDP 抽最大几个填充面，24 枚在 88px 下**全部不可读**（内部结构全丢）。线稿必须按上色稿的构成**重新 author**，不能机械抽取。

7. **看缓存不要靠猜，把 build id 打到 DOM 上。**
   `document.documentElement.dataset.build = BUILD_ID`，F12 一眼看出跑的是哪份代码。
   本地静态服务器不发 `ETag` 时，`Cache-Control: no-cache` 会让浏览器**直接复用本地副本**（表现为"先跳一下旧图标才变新"）。要 `no-store, must-revalidate`，并给 `<script>` / `<link>` 加 `?v=` 版本参数。

8. **合并两份同源文件要做逐字节 diff。**
   `app.js` 与 `app-art.js` 是 92% 相同的两份拷贝（44 个差异块，410 行差）。任何单边修改都要两边同步，否则 `index.html` 与 `index-art.html` 行为分叉。校验法：`ART_FILE` 块逐字符比对 + 函数名集合差集。

## 八、如果重做一遍，我的顺序

1. **量渲染尺寸**（1 单位 = 几 px）→ 定最小可见缝与描边档。
2. **写形状语言**：这枚图归"物体"还是"符号"？与同族其它 3 枚的区分点是什么？（先写下来，再画）
3. **先画 860px 定读法**，不看小图。
4. 读法过了再进 88 / 36 / 24 三档复核，此时才调描边与细节密度。
5. **最后才跑归一化工具**（bbox 收口、精压、体积）。
6. 全套通过后**逐字节 diff** 合并进项目，`node --check` + 四套断言（render / contrast / scoring / compliance）。
7. 真实页面逐格截图，确认继承样式、无闪帧、无跳版。
