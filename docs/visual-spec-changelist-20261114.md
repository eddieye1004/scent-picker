# V1 · 首屏锚点

**一句话**：第一屏现在没有任何「一眼记住」的东西，因为唯一可记的图形（圆盘）既没有边界，又被底部工具栏切掉了 50px，同时页头占了首屏 361px 里的 331px 去讲两句废话。

## V1.1 现状问题（打开页面实际看到的）

### 问题 1 · 页头吃掉首屏，且首屏有一处硬缺陷

1440×900 实测（`home-desktop`）：

| 元素 | 实测值 |
|---|---|
| `.masthead` | top 30，高 **162px** |
| `.masthead h1` | 46px / 行高 52.44，**占 52px 高、一行** |
| `.masthead .lede` | 15px / 25.8，**两行**（行顶 113 / 139），宽仅 435px（`max-width: 46ch`） |
| `.masthead .seal` | 30×30，**独占一行**，在其自己的一行里左对齐 |
| `.progress` | top **210** |
| `.q-title` | top 282 |
| `.disc` | top 361，**底 865** |
| `.actions`（吸底） | top **815** |
| 圆盘被工具栏遮挡 | **50px** |

三处实际可见的缺陷：

**① 页头导语被压成半行宽、折成两行，右侧一大片空白。**
`.lede` 宽 435px 而容器 656px，第二行只有「型号的候选」5 个字，读起来像被截断了。
这是 `max-width: 46ch`（`styles/src/80-specimen.css:131`）与 15px 字号叠加的结果：
46ch ≈ 435px，而文案 34 个字在 435px 里放不下。桌面端这里没有任何理由限宽——限宽是给长文段落用的，两行导语不是长文。

**② 印章「香」被挤成孤立一行。**
`.seal` 是 `display: inline-flex` 但它在 `.masthead` 里的前一个兄弟是 `<p class="lede">`（块级），
所以印章永远换到新的一行，`margin-left: 14px` 在同级盒里变成「比导语左缩进 14px」——
实测 seal left=406 而 lede left=392。屏幕上表现为标题下面孤零零一个小方框，偏移了 14px，
既不像印章（印章应该压在文字上），也不像标签（标签不该自己一行）。

**③ V1 的核心：首屏没有视觉锚点。**
`document.querySelectorAll('img').length === 0`，首屏唯一的图形是那一个 SVG 圆盘，
而它的「可记」程度已经被三件事削掉了：

- 扇区填充 `#FFFFFF`（对纸底 `#FAF7F1` 只有 **1.07:1**），扇区描边 `#E7E0D4`（**1.23:1**），
  盘外轮廓是 `box-shadow` 里的一圈 `#DED6C8`（**1.35:1**）。三者全在 1.4:1 以下——
  这不是「轻」，这是**看不见**。截图里圆盘的外沿是虚的，六块扇区靠中间那道黑圈才勉强成立。
- 唯一够黑的元素是盘心那圈 **2px 纯黑环**（`#14120E`，17.49:1），实测 `.disc-hub` 半径 166px，
  它成了整屏最抢眼的东西——一个空心的黑圈，圈里写着「香型轮盘 / 还没选 / 从外圈挑一个大类」。
  用户第一眼看到的是「还没选」三个字，不是任何能记住的形状。
- 圆盘底边 865 被吸底工具栏压到 815，**50px 被切掉**，实测 `sectorsBehindBar: ["东方琥珀调"]` ——
  「东方琥珀调」这个标签的下半截被切在工具栏下面（`bottom-desktop.png` 可直接看到：
  标签文字露在工具栏上沿之上，扇区本体在下面）。移动端同样，遮挡 24px。

**结果**：首屏是「一个大标题 + 两句被压窄的话 + 一个孤立小方框 + 一个看不见边界的圆盘 + 被切掉的底边」。
没有一处是「关掉页面还记得」的。

### 问题 2 · 首屏没有任何与「香水」有关的图像

全站 `images/` 有 **500 张**实物图，`icon-specimen/svg/` 有 **24 枚**上色香调图标（合计 295.6KB / gzip 80.1KB），
但首屏 `imgCount: 0`，`svgCount: 1`（就是那个圆盘）。
香调彩图只在**点了扇区之后**才进盘心（`app.js:1545` 的 `scentPlate`），
实物图只在**结果页**出现。第一屏因此完全没有任何「这是香水应用」的视觉证据——
纯看首屏，它可以是任何问卷工具。

## V1.2 改法

三条，**按优先级排序**，第 1 条是 V1 的主体，2、3 是配套（不修它们，第 1 条的效果会被抵消）。

### 改法 1（主体）· 把圆盘做成首屏唯一的「标本盘」

目标：让圆盘在首屏的第一个 100ms 就能被认出「这是一个可转的圆盘」，而不是一团白。

**1a. 给圆盘一条真正的边界。**
现在 `--stroke-l1: #C9C0B0`（对纸底 1.69:1）画在 `.wheel::after` 上，
而 `.wheel` 与 `.disc` 是同一个元素（`app.js:869` `class: 'disc wheel'`），
所以这条边其实生效了——但 1.69:1 在 504px 的圆上仍然读不出来。
改：外轮廓改用 `--edge: #6E675C`（对纸底 **5.23:1**），宽度保持 1px。
> 注意 `40-theme.css:277` 有一条注释明确说「外沿那道不能取 `--edge`……在 520px 的圆上会读成一圈发光箍」。
> 那条结论是**深色模式**下测的（`#8a8a8a` 对 `#14120E` 是 5.3:1，暗底上一圈亮灰确实像箍）。
> 浅色模式下方向相反：纸底上的一圈暖棕只是收边，不会发光。**所以只改浅色分支，深色分支保持 `--stroke-l1`**，
> 并在改动的 CSS 里把这条理由写清楚，避免下一个人照着旧注释改回去。

**1b. 让六块扇区之间出现「料」的差别。**
六族现在填充全部是 `#FFFFFF`（`70-final.css:204` 与六条 `[data-fam]` 规则全都写死 `fill: #ffffff`）。
改：填充分别取纸系四档的极小偏移，靠**极低差**建立「同一块料的六个切面」：

| 扇区 | 现在 | 建议 | 对纸底 |
|---|---|---|---|
| 柑橘 `citrus` | `#FFFFFF` | `#FDFBF7` | 1.03 |
| 花香 `floral` | `#FFFFFF` | `#FBF7F1` | 1.01 |
| 木质 `woody` | `#FFFFFF` | `#F7F2E9` | 1.01 |
| 东方琥珀 `amber` | `#FFFFFF` | `#F4EEE3` | 1.04 |
| 清新 `fresh` | `#FFFFFF` | `#F9F6EF` | 1.00 |
| 美食 `gourmand` | `#FFFFFF` | `#F6F0E6` | 1.02 |

差额全部控制在 1.00–1.04，**目的不是「看得出颜色」，是不再是一片死白**。
扇区缝保持 2.6px 不动（`70-final.css:205` 与 `30-wheel-refine.css:633` 两条都写过，
理由「1px 会糊成一片」是实测结论，不要动）。缝的颜色建议从 `--bg-3`（`#E7E0D4`，1.23:1）
提到 `--stroke-l1`（`#C9C0B0`，1.69:1）——**只提一档**，2.6px 的缝提到 `--edge` 会变成六条黑杠。

**1c. 把盘心那圈 2px 纯黑降下来，让边界成为最强的那条线。**
现在 `.disc-hub` 的 `box-shadow` 第一层是 `0 0 0 2px #14120E`（17.49:1），
它比外轮廓强 13 倍，视线自然全被它吸走。
改：2px → 1px，颜色 `--stroke-l3`（`#14120E`）→ `--ink` 保持深但降到 1px；
同时把 `1b` 那条外轮廓提到 5.23:1，让「外圈 1px 强边 + 内部弱反差」的层级成立。
> 这一条需要同时改 `20-wheel-core.css` 与 `80-specimen.css` 里两处 `.disc-hub` 的阴影
> （实测生效的是 `rgb(20,18,14) 0px 0px 0px 2px`，桌面 2px / 移动 1.5px，两档分别写在两处）。

**1d. 恢复一条「盘」的时间线索。**
`app.js:353-365` 仍然会往 SVG 里插 36 道分度刻线（`ring-tick`）、
一道 `ring-accent`、一道 `ring-spin`（缓慢旋转的弧），
但 `10-foundation.css:366-369` 把它们全部 `display: none` 了：

```css
.disc-svg .ring-thin,
.disc-svg .ring-accent,
.disc-svg .ring-spin,
.disc-svg .ring-tick { display: none; }
```

实测 `tickCount: 0`、`ringSpin: null`——**这些节点在 DOM 里存在但零渲染**。
改：**只开 `ring-tick` 一档**，取 `rgba(20,18,14,.10)`（对纸底 1.15:1），
36 道，`is-major` 那 12 道取 `.18`（1.28:1）。
理由：刻线是「这是一件仪器」的最短信号，而且它已经在 DOM 里、已经在 app.js 里算好了角度，
开一条 `display` 即可，**不需要新增任何 JS**。
`ring-spin` 与 `ring-accent` **保持关闭**——旋转弧在纸底上会变成噪点，且它是持续动画，
与 `prefers-reduced-motion` 的既有处理纠缠，属于「不必要的新风险」。

**1e.（可选，建议做）给六族各配一枚已有图标，放在扇区标签上方。**
`icon-specimen/svg/` 里已有全部 24 枚上色 SVG，`ART_FILE`（`app.js:703`）已把 24 个 subId 映射好，
`artInner()` 已实现「fetch + 内存缓存 + 同步读取 `ART_READY`」。
改：在 `.disc-sector.lvl1` 的 `.zh` 之前插一枚 20×20 的 `<span class="fam-glyph">`，
图取该族代表 subId（`citrus`→`citrus-cologne`、`floral`→`floral-rose`、
`woody`→`woody-sandalwood`、`amber`→`amber-amber`、`fresh`→`fresh-aquatic`、`gourmand`→`fruit-gourmand` 的现有映射）。
> **成本必须写明**：`artWarmAll()` 现在在结果页才被调用的话，首屏插图标就要提前预热，
> 首屏会多出 24 次 fetch（本地合计 295.6KB，gzip 80.1KB）。这违反首屏预算，**所以只预热 6 枚**，
> 其余交给结果页。这一条改动超过纯 CSS 范围，若 Eddie 只想要「不加请求」的方案，跳过 1e，1a–1d 已足够成立。

### 改法 2 · 压缩页头，把省下的高度还给圆盘

### 改法 3 · 修掉首屏唯一一处「像 bug」的东西

线上首屏第 1 帧没有缺陷，但如果从别的屏回到首屏、或首次渲染时字体未落地，
`h1` 里的 `<em>第一瓶</em>` 会以 `--blue #002FA7` 显示。
实测该 `em` 是 136×54、`color: rgb(0,47,167)`——它**本身没问题**（10.00:1，是产品识别色）。
真正的问题是它在 46px 衬线里**字重与前后文完全相同**，只靠颜色区分，
在「从零开始，找到**第一瓶**香水」里读起来像一条超链接（蓝色 + 同字重 + 在句子中间）。
改：加 `font-style: normal`（现在依赖浏览器默认，`em` 默认斜体但 Cambria 的合成斜体在这个字号下几乎看不出），
并把颜色从 `--blue` 换成 `--accent` 的同时**给一层下划线以外的强调**——
建议改为 `border-bottom: 2px solid currentColor`（2px 底线，不是 text-decoration，
这样在 46px 首行不会压到下行），让「第一瓶」成为首屏唯一被**画了线**的词。
> 这是一处小改，但它把首屏唯一的高分量彩色从「像链接」变成「像被标注的重点」。

# V2 · 问卷圆盘质感与层次

**一句话**：圆盘的「三层」现在只有一层有颜色（盘心那圈黑），另外两层（扇区、轮廓）对比度都在 1.4:1 以下；选项卡片则相反——未选中时是一张和纸底同色的方格（1.00:1），选中时整块填满 `#002FA7`，层级被压成「有」和「无」两档。

## V2.1 现状问题

### 2-1 · 圆盘的三个同心层，只有最内层有对比

实测（`wheel-desktop-empty`，`.disc` 504×504）：

| 层 | 实测 | 对纸底 `#FAF7F1` | 读出什么 |
|---|---|---|---|
| 扇区填充 | `rgb(255,255,255)` | **1.07:1** | 白纸 |
| 扇区描边（缝） | `rgb(231,224,212)` `#E7E0D4`，2.6px | **1.23:1** | 极淡的线 |
| 盘外轮廓 | `#DED6C8`，`box-shadow` 第 1 层 | **1.35:1** | 几乎看不出 |
| 盘心环 | `rgb(20,18,14)` 2px（移动 1.5px） | **17.49:1** | 一条黑圈 |

四档跨度 **1.07 → 17.49**，中间三档全挤在 1.4 以下，最内层一下跳到 17.5。
这不是「层次」，这是**两级**：看不见的底 + 一个黑圈。
`wheel-desktop-selected` 里选中扇区换成 `--fill-blue` 之后更明显：
选中一块蓝，其余五块全是 1.07 的白，中间一道 17.49 的黑环——
三层结构（外轮廓 / 扇区 / 盘心）在视觉上只剩「蓝、白、黑」三种互不相干的色块。

### 2-2 · 装饰环写了但全被关掉，DOM 里躺着 36 个不渲染的节点

`app.js:353-372` 每次建盘都会插：
- 36 道 `.ring-tick`（每 3 道加长，`is-major`）
- 1 道 `.ring-accent`（`rIn - 16`）
- 1 道 `.ring-spin`（`rOut - 3`，缓慢旋转）
- 1 道 `.ring-thin`（`rOut + 6`）

实测 `tickCount: 0`、`ringAccent: null`、`ringSpin: null`、`ringThin.opacity: "0"`、`display: "none"`
（`10-foundation.css:366-369` 一条规则全关）。
**这是「代码里有一套仪器语言，界面上一点也没有」** —— 属于典型的「写了没生效」，
和 V1 的 1d 是同一个根因。（`wheel::after` 同样：`20-wheel-core.css:1422` 与 `:1496` 两个 `.wheel::after {}` 是**空规则块**，
`60-motion.css:97` 与 `40-theme.css:280` 才是真正给 `box-shadow` 的两条；空块留着会误导读代码的人。）

### 2-3 · 盘心内接正方形与内弧「咬合」的关系，被黑环吃掉了

`10-foundation.css:422` 的注释解释了盘心为什么取 42.7%（内接正方形，四角顶到内弧）：
> 「盘心缩在内圆中央时，四周留一圈 39px 的白，方块和内圈没有任何几何关系，读起来像『贴在圆盘上的一张卡片』」

设计意图是「方与圆互相咬合」。但 `.disc-hub` 的 `border-radius: 50%`（实测 `hubStyle.radius: "50%"`）
—— 盘心是**圆**，不是方，四角咬合这件事不存在。
而黑环 2px 把盘心从盘面里「切」了出来，读成「圆盘中央贴了一个小圆盘」，不是「盘心」。
**注释描述的设计（方角咬合）与实际渲染（圆 + 粗黑环）不是同一件事。**

## V3.2 改法

### 改法 1 · 修掉吸底条盖住购买链接（先修这个，其余都是优化）

三条路，**建议 1a**：

- **1a（推荐）**：`.actions` 在**结果页**不吸底。
  判据：`#app[data-step="result"]` 时 `.actions` 改 `position: static`。
  理由：结果页的 `.actions` 只有「重新来一次」一个按钮（实测 `.actions` 685 宽、按钮 116 宽，右侧空 500px），
  它不需要常驻——用户滑到底自然会看到。而问卷页的「下一步」必须常驻。
  改动只有一条选择器 + 一个媒体查询作用域，**风险最低**。
- **1b**：给 `.actions` 加 `padding-bottom: env(safe-area-inset-bottom)` 并给 `body` 加同位 `scroll-padding-bottom`。
  这只解决「滑到底时最后一块被遮」，不解决「首屏第 1 张卡的购买行被遮」——**不够**。
- **1c**：把 `.pick-foot` 从卡片内移到卡片下方的独立行。改动大，会破坏「购买链接属于这一瓶」的语义。**不建议**。

> 无论选哪条，**都必须实测验证**：结果页 `footBehindBar === false`（桌面与移动各一次），
> 这是本腿留下的可直接复用的判据。

### 改法 2 · 重排首屏的层级顺序：让「瓶子名」成为最大的一行

目标：**答案最大，条件次之，页头最小**（现在是页头最大、答案第三）。三条：

**2a. 结果页的页头降级。**
`.masthead h1` 在结果页仍是 46px（与首页同尺寸），而结果页的第一内容已经由 `.result-head` 承担。
改：`#app[data-step="result"] .masthead h1` 降到 **28px**，`.masthead .lede` 降到 13px 或直接隐藏
（它写的是「每一瓶的理由都能反推回你刚才的选择，没有一句是编的」——这句话在结果页是**元话语**，
每个用户都会读，但不影响任何决策）。
> 省下：h1 从 52px 高降到约 32px；lede 桌面本就一行，移动端两行→零。合计桌面 20px、移动 72px。

**2b. `.result-head h2`（条件摘要）从 34px 降到 22px，与卡片名同档。**
它现在是「柑橘调 · 浓郁度 3/5」，是**筛选条件**不是主张。降到 22px 后与 `.pick h3` 同档，
层级上「条件 = 答案同级」，而「答案」靠 2c 的加粗/字号再拉开。

**2c. `.pick h3`（香水名）从 21px 提到 26px，字重 400 → 500。**
这是 V3 的核心一条。21px 的衬线在 14px 的品牌行上方只高 7px，扫读时两者。
提到 26px + 500（InterVar/NotoSC 的可变字体轴支持真实 500，不再是 YaHei 时代的塌成 700），
名字与 meta 拉开到 12px 差，一眼能分出「这是什么」和「谁做的」。
> 字号上限受 `scripts/test-contrast.mjs` 的 12px 下限约束——**上限没有约束**，
> 但要验移动端 390 宽：`Eterna Man Limited Edition` 这种 24 字符名字在 26px 下会折 2 行。
> 实测第 3 名名字已较长，**建议 26px 只给桌面，移动端 22px**，用 `@media (min-width: 621px)` 分开。

**2d. `.profile-line`（匹配度口径说明）从卡片之前移到卡片之后。**
它现在 top 347、在 `.pick`（top 432）之前，33px 高、12px 等宽、占满整行宽。
移动端更糟：54px、两行。
改：移到第三张卡之后、`.foot-nav` 之前，字号从 12px 提到 13px（它现在是全站唯一一处
「12px 等宽 + 满宽 + 多行」的组合，读起来像法律条款）。
> 理由：这是**方法论说明**，用户在看到结果之后才可能关心「这个百分比怎么来的」。
> 放在结果之前，等于让人先读免责声明再看答案。

### 改法 3 · 给第 1 名一个不与栅格冲突的视觉身份

现有三个信号里，顶线是唯一真看得见的，徽标是蓝的但只有 21px 高，**编号上色是死的**（见 3-3）。
在不重建「左边框 + 内缩」的前提下（那会破坏编号对齐，v35 已否决），补三个手段：

**3a. 先把那两条互相拆台的规则修掉——这是本项里最便宜、命中率最高的一条。**
`10-foundation.css:1520` 把 `.pick-rank .n` 从选择器组里摘掉，
让 `:930` 的 `color: var(--accent)`（= `#002FA7`）真正生效。
效果：第 1 名的「候选 01」变蓝、第 2/3 名保持墨黑——**三重信号立刻全活**，
零新增 CSS，只删一个选择器。
> 必须验的副作用：`:1520` 那条规则的另一半是 `.masthead .lede em`，它让首页 `.lede` 里的 `em` 收墨。
> 本改动只摘 `.pick-rank .n` 一项，其余选择器不动。改完 `test-contrast` 必跑
> （`PAIRS` 里有 `--accent on --bg-2` 一条，指向的正是 `.disc-hub .hub-zh`，不受影响）。

**3b. 第 1 名整卡吃一层极浅的水洗底。**
`background: var(--blue-wash)`（`rgba(0,47,167,.07)`，对纸底 1.05:1）+ 左右各 `-8px` 的 `margin` 反补
（`margin: 0 -8px; padding-left: 8px; padding-right: 8px`），让底色比文字宽一点，
读成「这一张被单独圈出」而不是「这一张被塞进盒子」。
> 水洗底只有 1.05:1，**不会**破坏 `test-contrast` 的 43 项（`--ink` 压水洗底仍 ≥ 17:1），
> 但足够让三张卡在扫读时出现「一张有色、两张没色」的差。

**3c. 把 `top-badge` 从内部术语改成用户语言。**
实测文案是 **`原始分最高`**（`app.js:3634` 的 `topBadgeText(hasPct)`）。
这是排序实现的术语。建议在 `matchPct != null` 时用 `最匹配`，否则用 **`最接近你答的`**。
> 一处文案改动，`app.js` 的 `topBadgeText()`。

**3d. 修 `.pick-foot` 的换行抖动（3-4 的根因）。**
`.pick-foot` 的 `flex-wrap: wrap` 让第 1 名的购买组刚好挤进一行、后两张被挤到第二行，
造成 39px 的高度差——**第 1 名反而比后两名「薄」**。
改：给 `.pick-buy-group` 加 `flex: 0 0 auto`，让它永不被压窄换行；
若仍换行，则给 `.pick-foot` 一个明确的 `row-gap`（现在靠 `gap: 10px` 同时管横纵），
让换行是**可预测**的而不是取决于品牌名长度。
> 这一条不追求「三张卡等高」（理由条数与数据真实相关，不该为对齐砍内容），
> 只追求「等高或等矮**由内容和规则决定，不由临界值决定**」。

### 改法 4 · 统一卡片语法：处理页面底部那张 `SCENT PROFILE` 小卡

两种做法：

- **4a（推荐）**：`.share-card` 保留圆角与底（它确实要当「截图发出去」的卡片用），
  但在结果页里给它一个**标题**说明它是干什么的（现在是凭空出现的一张卡，用户不知道它能存/能截图）。

- **4b**：改成与结果卡同样的语法（无底、只有顶线）。**不建议**——`80-specimen.css` 已写明
  它之所以用 `--bg-2` 底 + 边框，是因为「与页面同色时截图的边缘会和背景融在一起」。

> 4a 的实质是「加一行字解释一个已有组件」，不改任何视觉参数，**属于最低成本的层级修复**。

### 改法 5 · 匹配度百分比的呈现（可讨论，列出供决策）

现在 `.pick-rank .score` 是 12px 等宽大写、`--ink-3`（6.59:1），

> 所以 16px 的效果无法在改造前截图中验证。**列为待定，不作为 V3 的必做项。**
