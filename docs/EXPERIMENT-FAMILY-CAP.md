## 1. 为什么这个实验值得做

诊断（`docs/reviews/QUESTIONNAIRE-LINE-REVIEW-20261110.md` §3.1）实测：家族三项合计 86 分
（familyPick 34 + emotionFamily 30 + occasionFamily 22）在**整族候选池内是常数**——
柑橘 L1 池 117 瓶全部拿满，木质 239/243 并列。

假设：这一项既然是常数，它只抬高所有瓶的基数、不参与区分；把它压小，剩下约 49 分
（intensity 18 + character 16 + season 10 + timeOfDay 6 + temperature 14 + sweetness 13 …）
的相对权重就会放大，排序分辨率应该变好。

## 2. A 方向：家族总分封顶

### 2.1 两种压法（派单要求两法都测）

- **scale**：`famScore = clamp01(famHit/famDenom) * cap`，等比缩小，中低分瓶一起被压小。
- **hard**：`famScore = min(clamp01(famHit/famDenom) * 86, cap)`，只削顶部，中段保持原值。

两者在 `base = 1`（饱和瓶）处相等，差别全在 `0.4 < base < 1` 的中段。

### 2.4 为什么 scale 在 40–50 区间动不了命中率

**机制一：家族项是常数，等比缩放不改变瓶与瓶的相对顺序。**

`scale` 下 `famScore = base * cap`，对同一个画像，所有候选瓶的 `base` 同乘 `cap/86`。
`base` 相同的瓶（饱和瓶之间）永远同分，`base` 不同的瓶之间**差值也同比例缩小**——
换句话说，家族项的**区分力**没有增加，只是所有瓶的总分一起变矮，其它因子的绝对分差
相对变大。实测分辨率完全没变：

```
woody 入口（L1 池 243 瓶全量）：
  cap=86   不同总分  41 档 · 最大并列 43 瓶
  scale 50 不同总分  41 档 · 最大并列 43 瓶
  scale 40 不同总分  41 档 · 最大并列 43 瓶
```

**机制二：金标准一半的瓶子被 L1 硬过滤挡在池外，压顶碰不到它们。**

`recommend()` 的 `isDominant` 是**硬过滤**（`scoring.js` 845-855），判据是「该瓶 families 里
权重最高的那一族，等不等于用户选的族」，与家族项拿多少分**无关**。逐画像实测：

| 画像 | gold 在 L1 池 |
|---|---|
| P01 | 0/5 |
| P02 | 2/5 |
| P03 | 2/5 |
| P04 | 1/5 |
| P05 | 4/5 |
| P06 | 3/5 |
| P07 | 4/5 |
| P08 | 3/5 |
| P09 | 3/5 |
| P10 | 1/4 |
| P11 | 4/5 |
| P12 | 5/5 |
| **合计** | **32/59 = 54.2%** |

其余 27 瓶即使家族项拿满分也进不了候选池。所以家族封顶最多只能影响 32 瓶，
而这 32 瓶里已经有一部分本来就排第一（P02/P05/P09/P11 的 L1 内最好一瓶排第 1）。

**机制三：池内可争取的那几瓶，差的距离远超封顶能挪动的量。**

L1 内最好的 gold 瓶实际排名：P03 第 15、P06 第 14、P10 第 18、P12 第 20；
P04/P07/P08 的 L1 内 gold 全部在 top30 之外。要翻进 top3，得跨越 11–17 个名次，
而封顶在 40–50 区间对单个瓶的相对位移不到 5 分。

### 2.5 cap≤30 的 STRICT +1 为什么不能用

`cap=30` 起 STRICT 从 4/12 变 5/12，且经「香水库数组反转」检验仍成立（不是并列抖动）。
但：

- **MAJORITY 始终 ±0**，唯一变化是 P06 的 top1 翻成 gold `mfk-grand-soir`；
- **领先幅度只有 0.84 分**（新 top1 99.58 vs 第二名 98.74）。这是「刚好越过」级别的效应，
  换个数据版本就会消失；
- cap 要压到 30（比派单区间 40–50 低 1/4），已超出派单授权范围；
- 压到 cap=6 时 MAJORITY 反而变 1/12 —— 继续往下压会开始伤到已有命中。

### 2.6 hard 为什么更差

`hard` 把 `base*86 > cap` 的瓶子**全部顶到同一个 cap 值**，等于在 cap 这个分位上新造一个
大并列平台 —— 削掉了顶部的区分，却在半山腰堆平。实测不同总分档数从 41 掉到 38：

```
基准      不同总分 41 档 · 最大并列 43 瓶
hard 50   不同总分 38 档 · 最大并列 43 瓶
hard 40   不同总分 38 档 · 最大并列 43 瓶
```

这也解释了为什么 `hard` 的六档结果**逐字节相同**：只要 cap 低于中段瓶的值，中段瓶就都被
顶到 cap，档位再低也不改变相对顺序。

## 3. B 方向：notes 层加权

### 3.1 在 A 最优档上叠加

A 的最优档按「MAJORITY 优先 → STRICT → 更接近区间中点 45」选出 **scale cap=26**
（MAJ 2/12 · STR 5/12）。B 全部在此档上叠加：

| likedNotes 权重 | MAJORITY | STRICT | ΔMAJ | ΔSTR |
|---|---|---|---|---|
| 14（默认） | 2/12 | 5/12 | ±0 | +1 |
| 28 | 2/12 | 5/12 | ±0 | +1 |
| 56 | 2/12 | 5/12 | ±0 | +1 |
| 112（8 倍） | 2/12 | 5/12 | ±0 | +1 |

**四档逐位相同**，与 A 最优档本身也逐位相同。

### 3.2 原因是结构性的：这批画像没有 notes 层输入

12 个金标准画像的答案里：

| 输入项 | 有该输入的画像数 |
|---|---|
| `likedNotes` | **0/12** |
| `subfamily` | **0/12** |
| `anchorNotes` / `anchorPerfume` | **0/12** |
| `emotion`（走情绪入口才有 `emotionNotes`） | **0/12** |

`likedNotes` / `emotionNotes` / `subfamilyHits` / `anchor` 四个 notes 层因子的分子全部是
`hitsOf(某个集合)`，集合为空 → 命中 0 → 得分 0。**权重乘任何数都是 0 × k = 0。**

因子平均贡献全表（12 画像 × top20 候选）证实这一点：

| 因子 | 平均贡献 |
|---|---|
| family | **78.87** |
| intensity | 15.73 |
| character | 15.65 |
| temperature | 12.44 |
| sweetness | 11.67 |
| season | 10.00 |
| timeOfDay | 6.00 |
| popularity | 3.31 |
| **notes 层四项合计** | **0.00** |

### 3.3 诊断档（非生产方向）：给 notes 层灌入输入后会怎样

把第 1 步所选家族的 `representativeNotes` 当 `likedNotes` 灌进去（这只是**诊断**，
真实问卷若要问香调属问卷层改动，不在本轮权限内）：

| likedNotes 权重 | MAJORITY | STRICT | ΔMAJ | ΔSTR | top3 换手 |
|---|---|---|---|---|---|
| A 最优档（无 likedNotes） | 2/12 | 5/12 | ±0 | +1 | 5/12 |
| 诊断 14 | **0/12** | 3/12 | **−2** | −1 | 10/12 |
| 诊断 28 | 0/12 | 3/12 | −2 | −1 | 10/12 |
| 诊断 56 | 0/12 | 3/12 | −2 | −1 | 10/12 |

**有了输入反而大幅变差**（MAJ −2）。原因是「家族代表香材」与「用户真正要的香调」不是一回事：
给 citrus 的所有画像灌 bergamot/lemon，会把只想要某一种柑橘的画像推歪。
这一档说明**不是「notes 权重不够」，而是「以家族代表香材代替真实香调偏好」这条路本身错**。

## 4. 判定与应该记下的教训

按派单第 C 条：A、B 都无效 → 如实记录并停下，不自换方向。

| 结论 | 证据 |
|---|---|
| 家族封顶在 40–50 区间对 MAJORITY 零效果 | scale 三档全 ±0，top3 换手 3–5/12 但命中率不动 |
| 家族封顶不是「压得不够狠」 | 压到 cap=12/6 才动，且 cap=6 开始伤 MAJORITY |
| hard 削顶会造新并列平台，比 scale 更差 | MAJ −1，不同总分档数 41→38 |
| notes 层加权当前无法生效 | 12 画像 notes 输入 0/12，贡献 0.00 分 |
| 金标准的可达上限被 L1 硬过滤锁住 | 27/59 gold 不在 L1 池，封顶赋能为零 |

**本轮最该记住的一条**：家族项的问题不是「它太大」，而是「它在一个族内是常数，且
候选池本身已经把 46% 的金标准答案排除在外」。压小常数不产生信息；要提升命中率，
需要动的是**池的准入**（isDominant 硬过滤）或**金标准与画像的对应关系**，
这两件事都超出本轮派单范围，须另行裁决。
