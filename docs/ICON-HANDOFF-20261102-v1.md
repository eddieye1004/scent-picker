| 项 | 实测 |

| 图元数 | 2（rose / oud）– 9（vetiver），中位 4 |

### 2.6 总览页的梯度 id 重复

`icons-24-overview.html` 内 82 个 `id` 各出现 2 次 —— 64px 段与 36px 段是同一份卡片 markup 的两次拷贝。浏览器按文档顺序解析，第二段解析到的是第一段的渐变（stop 完全相同），视觉无差，但属于**潜在缺陷**：一旦两段渐变被分别修改，第二段会静默失效。

## 三、本轮（2026-10-31 → 11-01）已积累的经验与规则

### 3.1 规格（沿用，不要重新发明）

| 项 | 定稿值 | 依据 |
|---|---|---|
| 画布 | `viewBox="0 0 24 24"`，不设额外尺寸属性 | 9/9 范本一致 |
| 安全框 | 内容落在 **3.3–20.7**（四边 ≥3.3 单位 = 13.75%） | 9/9 范本 |
| 主轮廓描边 | **0.85–1.00** | 9 枚实测 0.60–1.00，取上半区 |
| 内部纹理描边 | **0.22–0.50** | 同上 |
| 渐变 | 同色相 `linearGradient`/`radialGradient`，HSL 明度差 **18–36.5%**（既有 24 枚实测区间 12.9–38.8%） | 与既有区间重叠 |
| 层间明度差 | 14–22% | 范本提炼 |
| 图元数 | 4–30（粉感 73 是粉粒特例，**不复用**） | 中位 22 |
| 单枚体积 | ≤ 30 KB | 中位 21.4，范围 7.2–36.8 |
| 禁用 | `filter`、`clipPath`、外层 `<g transform>`、多色相渐变、投影 | 4/4 合规实测 |

### 3.2 工程规则（踩过坑换来的）

1. **渲染尺寸不是 24px**。实测 `.plate-svg` 在 1440 视口是 **88×88**、390 视口 **36×36**。按 24px 校间距是前 20 余版失败的第一原因。1 单位 = 3.67px（88px）/ 1.5px（36px）。
2. **最小可见缝 ≥ 2.5 单位**（描边 1.5 + 缝 1.0）。相连笔画中心距 ≈ 描边宽时，小尺寸下糊成黑块。
3. **禁止外层 `<g transform="scale()">`**（样张侧）。坐标落在非整数像素，整条线发灰。运行时侧例外：`SUB_FIT` 就是靠 `translate+scale` 归一，但线宽必须按 `1/k` 反补偿。
4. **花瓣 `wid` 是半宽，总宽 = 2·wid**。v8 把 wid 当总宽 → 五瓣互吞成五边形。
5. **瓣尖不能用 `sin(π·t)` 收口**——那永远收敛到一个数学点，就是「尖刺/星芒」的真来源。v13 定稿：瓣尖接半径 `capR = wid` 的半圆帽，半宽剖面 `w(u)=wid·sin(π/2·u)^0.9`。
6. **花瓣比例定死：总宽 = 长 × 0.62–0.66**（`wid = len × 0.31–0.33`）。
7. **渐变的 `url(#id)` 必须自证**：每个引用都要有对应定义，缺失 0 处；同文档多份拷贝时 id 不能重复（见 2.6）。
8. **母题为先**：先立「母题类 / 纹理方向 / 色相 H+L*」三列区分矩阵，再画。同族内母题类不得重复、纹理方向不得重复、色相不得过近（ΔL*<6 且 Δh<18 判冲突）。
9. **每一版的「否决记录」必须写下来**。本轮 16 枚里有 9 枚是否决了 2–5 个读法后才定稿的（香根草否掉 5 个：扫把/耙子/蜘蛛/蘑菇/栅栏），这些是最高价值的资产。
10. **描边 ≠ 填充两套语言**。上色版走填充+描边；运行时走纯描边 fill:none。**同一枚在两套里的读法可能完全不同**（如 `oud` 上色是料块+密纹，线稿是不规则多边形+开口弧）。
11. **改动必须能逐字节自证**：本轮只重画 3 枚，脚本里显式断言「未参与合并的 21 枚逐字节相同 21/21」。
12. **备份走 MANIFEST.sha256 + 时间戳目录**，不靠 git（`/scent-picker/` 在 `.gitignore` 第 22 行，整个项目不入库）。

### 3.3 撞形判据的适用边界

88px 像素掩膜两两 IoU 只适用于**同族内防混**与「24 枚嵌进一个盘时的相互辨认」，**不适用于跨族**。跨族靠构图语言分开：木 = 块料、柑橘 = 整果带叶、花 = 中心放射、清新 = 单片叶/波纹。

## 五、下一步优化方案（待确认后执行）

### 5.1 优化方向（三条，按优先级）

| 方向 | 内容 | 为什么现在做 |
|---|---|---|
| **A. 补欠账：运行时线稿 24 枚重绘** | `app.js` `SUB_MARKS` 整块重画，`SUB_FIT` 重算 | 唯一硬缺口。3 枚合并图标语义不成立（`woody` 画的是被合并的干燥木质），用户在实际页面里看到的就是这个 |

### 5.2 范围（明确不做什么）

- 不改 taxonomy（24 类结构已定稿）
- 不改总览页版式（4 列 / 64px + 36px 两段 / h2 分组 / 配色）
- 不改读法/母题（已过用户确认的方案不再翻案）
- 不改 `app.js` 的 `scentPlate()` 渲染逻辑
- 不碰合并前遗留的 7 枚 SVG（`svg-v14-absorbed/` 归档保留）

### 5.3 预期结果（可验收）

| 方向 | 验收指标 | 当前 → 目标 |
|---|---|---|
| A | `SUB_MARKS` / `SUB_FIT` 24/24；三枚合并图标不再复用被合并项图形；test-render 全绿 | 24/24 但 3 枚语义错 → 24/24 且语义正确 |

### 5.4 执行顺序（分三步，每步可独立验收）
