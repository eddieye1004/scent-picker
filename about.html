关于

这个工具是干什么的

给不懂香水的人用。不是「猜你喜欢」的黑盒，每一瓶为什么推给你都能反推。

给谁用

给一瓶香水都没有、或者买过但不知道自己买了什么的人用。 典型场景是这样：想买第一瓶，搜到一堆「必买清单」，每个名字都没听过； 或者看别人说「木质调好闻」，却不知道自己是不是喜欢木质。

这个工具假设你不认识任何香调术语。所以它不问「你喜欢馥奇调还是西普调」—— 那对一个新手是没有信息量的问题 —— 而是问你闻着舒不舒服、什么时候用、想要多浓。

怎么用

两套入口，走完一次大概两三分钟：

选一个大方向 圆盘上挑香型（柑橘 / 花香 / 木质 / 东方琥珀 / 清新 / 美食）。不确定就只挑外圈，中圈是可选收窄。
点名的味道：想要的 / 受不了的 58 个常见香调里点选。跳过也行 —— 点名「受不了」比点名「想要」更有效，因为讨厌的东西没有替代品。
气质 想要它给人什么感觉（清冷 / 温暖 / 干净 / 神秘…）。这一屏同时决定冷暖与甜度两个维度。
场合 / 季节 / 浓淡 同一瓶香在办公室和约会里表现完全不同。季节和浓淡都可以跳过，不答不扣分。
已经试过并且喜欢的 这一屏是可选的，但如果有，它是信息量最大的一题 —— 它是「你实际闻过并喜欢」的真实反馈，不是偏好声明。
结果页：3 瓶候选 每瓶给前调 / 中调 / 后调、一句能反推回你某个答案的理由、以及保管建议。

关于购买链接

结果页上有购买入口。其中带联盟推广关系的链接会在页脚一行披露， 页面源码里对应 rel="sponsored"。通过它们成交本站可能获得佣金， 不影响你的支付价格。没有佣金关系的入口（站内搜索兜底）不标 sponsored。

当前链接覆盖：淘宝 661 / 1388 瓶，京东 1 / 1388 瓶 （数据 data/affiliate-links.json 的 coverage 字段）。 覆盖不满的部分走站内搜索兜底，不是所有瓶都点得进商品页。

数据怎么来

香水库来自 Scento Perfume Database 的开放数据集，许可 CC BY 4.0， 2026-11-01 快照。经清洗、家族映射与字段裁剪后已修改，逐字署名与许可声明 写在页面页脚与 README.md 里。

推荐是怎么算出来的

纯规则打分，不调用任何大模型。每个因子（家族、香调命中、浓度、季节、冷暖、甜度…） 有固定权重，加总排序；结果页的理由是模板拼装，不是生成文本。 这样任何一条推荐都能反推到某个具体答案 —— 这也是它和「AI 猜你喜欢」最大的区别。

我们怎么知道它准不准

有一份12 个人设画像的人工金标准用来防回退。当前成绩： top3 里命中 ≥2 瓶的画像 = 2 / 12，top1 命中的 = 4 / 12。

这个数字不高，我们不掩饰。原因已经定位：这套金标准量的是 家族与气质维度，而香调维度的判定轴与它不对齐（详见仓库 CONTROL.md §5 的收口结论）。所以它守的是 「改动不许让结果变差」，不是「已经很准」。

另有一套 notes 专用小金标准（8 个香调意图明确的画像）， 当前 0 / 8 与 1 / 8。它同样只用来防回退。

已知局限

  • 持香与扩散是按浓度推断的，不是实测 —— 源站没有这个字段。
  • 不展示价格、不做比价。价格随时变，抓不准的东西不编。
  • 库容随上游更新，可能仍选不到你已经知道的那一瓶。
  • 家族是多标签的：一瓶香水往往同时属于几个家族，所以「这是木质调」不等于「它只有木质」。这也是金标准成绩偏低的原因之一。
  • 没有用户账号、不存任何作答。所有计算在浏览器本地完成，刷新即丢。

技术上

零构建的静态站：原生 ES module + 一份手写 CSS，没有打包器、没有框架、没有运行时依赖。 打分逻辑在 src/scoring.js，香调匹配在 src/notes.js。 仓库带 306 项渲染断言与 43 项无障碍断言（对比度 / 字号 / 焦点环 / 触控目标）。
