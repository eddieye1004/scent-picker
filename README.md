# 零基础香水选择器

**用一次问卷（家族入口 8 屏 / 情绪入口 9 屏），从一个完全不懂香水的人，走到具体某瓶香水的名字。**

不是"猜你喜欢"的黑盒推荐。每一瓶都给你完整的前调 / 中调 / 后调，以及**能反推回你刚才某个答案**的推荐理由。

---

## 它解决什么问题

新手买香水最常踩的坑，不是"买不到好香水"，而是**顺序错了**：

1. 先看别人推荐的具体香名 → 买了发现自己晕白花 / 讨厌甜 / 受不了皮革
2. 不知道香水按家族分，只看"好闻"两个字，实际无从判断
3. 前中后调看不懂，以为香水是"一个味道"

所以这个工具的顺序是反的：

```
先定大方向（家族）→ 再缩范围（场合 + 浓度 + 香调）→ 最后给具体香名 + 三调 + 理由
```

---

## 核心用户流程

前两步是**环形圆盘**（仪表盘交互），后两步是滑杆与香调标签。

| 步 | 问题 | 为什么这么问 |
|---|---|---|
| 1 | 你闻着舒服的，是哪一类味道？（圆盘：柑橘 / 花香 / 木质 / 东方琥珀 / 清新 / 美食） | 先定大方向。不确定就只挑外圈，中圈是可选收窄 |
| 2 | 有没有特别想闻到的味道？（可跳过，58 个可选香调） | 点名具体香材比挑大方向更准 |
| 3 | 有没有完全受不了的味道？（可跳过，同上 58 个） | **点名"讨厌"比点名"喜欢"更有用** —— 排除比加分更准 |
| 4 | 你希望它给人什么感觉？（清冷 / 温暖 / 干净 / 神秘 / 明亮 / 慵懒…） | 绕过"香调术语"，直接问感受。这一屏同时决定冷暖与甜度两个维度 |
| 5 | 主要什么时候用？（上班上课 / 约会 / 日常居家 / 正式场合 / 运动户外） | 同一瓶香在办公室和约会里表现完全不同，场合决定了扩散与浓度的上限 |
| 6 | 主要在哪个季节用？（可跳过） | 决定它会不会在夏天闷、冬天散太快 |
| 7 | 想要多浓？（体感 1–5 + 浓度类型 EDT/EDP…） | 把抽象的"浓度"翻译成"多远能闻到、能留多久" |
| 8 | 已经试过并且喜欢的？（可跳过） | 唯一基于"真实闻过"的反馈，信息量最大的一题 |

> 家族入口共 **8 屏**；走情绪入口时多一屏「整族排除」（不想再看到木质就整族关掉），共 **9 屏**。
> 步数由 `app.js` 的 `STEPS` 数组决定，`scripts/test-render.mjs` 有断言钉住（`共 8 步` / `共 9 步`）。

圆盘不是纯 SVG：扇形用 SVG 画，可点区域是盖在上面的真实 `<button>`，所以触控目标 >= 44px、键盘 Tab 进得去、方向键能在扇区间漫游。

盘心的形态跟着选择推进，三态不同：

- **没选大类**：盘心填满内孔（直径 66%，恰是内孔 2×158/480 = 65.83%），是圆不是方——圆形盘心接圆形内孔，接缝才是同心的。取内接正方形会在四周留一圈白，读起来像「环 + 贴在环上的一张卡」。
- **选了大类没选小类**：圆盘缩到 56%（窄屏 60%/58%），四周让出一圈等分弧段放子家族；盘心转透明，只有文字。**这一态不能用深底**——用户还没落到具体某一味，翻深会让人误以为已经选定。
- **落到具体小类**：盘底不动（仍是 `#f5f5f5`，与展开态同一个底），改用三层同时表达——盘底加一圈 `--blue-amb` 发丝描边表示「这个盘现在是激活的」；**被选中的那一段弧自己填实 `--blue` + 白字**（面积小、对比 10.69:1、位置明确）；盘心文字回墨色系，底部长出标本线稿。

  为什么不整盘翻墨：翻了就等于用「整块变色」表达「你选了其中一格」，反差过大，用户会先觉得「页面切走了」。参考 Apple 与 Oura，选中由被选中的那个小元素自己表达。**连带的坑**：底板变浅后线稿必须从白线换深线，否则白线画在白盘上等于图形消失——换底不换线是改配色最容易漏的一处，已有断言守门。

标本线稿是自绘 SVG（`viewBox 0 0 24 24`、无填充、圆头端点），**每个小类一枚专属标识**（`SUB_MARKS`，24 枚），画的是该小类**代表香材本体**而不是抽象符号：柠檬=横置尖椭圆、佛手柑=带颈梨形、橙花=五瓣、葡萄柚=正圆厚皮分瓣、香根草=扇形根须、皮革=圆角皮片+8 缝线孔、酒香=酒杯轮廓。

只画一枚而不是每味香材一枚：每个小类的代表香材**全部落在同一个家族里**（白花 = 茉莉 + 晚香玉，都是 floral；果味甜 = 桃 + 苹果 + 梨，都是 gourmand），逐味画会出来一排一模一样的图标。查不到专属标识时才退回家族母题（柑橘横切 / 花瓣 / 年轮 / 树脂滴 / 叶 / 豆荚）——**宁可退回家族图，也不画一个假的专属图**。香材名交给下面那行 12px 小字，完整清单在 `aria-label` 里。

深色模式（`prefers-color-scheme: dark`，不做手动开关）：不是把白纸翻黑，而是把明度轴反向后重排——`--bg-3` 在浅色里比 `--bg` 深、在深色里必须比 `--bg` 亮，因为它的语义是「更平/更凹的底」。三档墨色按深底**反解**（`--ink-3` 对 `#141414` 是 6.0，照搬浅色值会掉到 2.4）；主色从 `#002FA7` 提到 `#6E8BFF`（前者对深底只有 1.9:1）。六族渐变**重新定色**而不是压暗——`brightness(.26)` 会把六个色相抹平成同一种深灰（实测过），深色版在 L* 12–16 的窄暗区间里改用色相拉开距离。浅色模式经 HEAD/工作区逐像素 A/B（两视口 × 三态）验证 **0 差异**。详见 [D53](docs/DECISIONS.md)。

24px 下三条硬限制：两个相邻小圆点会被读成一张脸（不留并排小圆）；不与主形同心的线段会被读成螺旋（内部线必须对称或贯穿）；外轮廓差异远大于内部细节差异（优先换轮廓，内部线不超过两条）。

「有专属标识」不等于「有辨识度」——**同族内部不许撞形**。判据不是图元数（`vetiver` 一束五根曲线打包在一条 `path` 里、`spicy-amber` 就该一笔到底），而是把所有枚按族摊成 96px 与 44px 两档并排给人眼过一遍，再用光栅化 IoU 排序找嫌疑。**IoU 只能排序、不能判决**：它对描边宽度极度敏感，`mossy` vs `woody-aromatic` 只有 0.447 却是同一张图，`white-floral` vs `vetiver` 0.612 却没人会认错。跨族撞形不用管（外圈一次只展开一族，用户看不到两族并排）。本轮据此重画了两处：苔藓木质从「主枝 + 短枝 + 顶珠」改成「树皮横线 + 一丛短毛」（苔藓本就没有主干、也不成枝），香草甜从「竖椭圆 + 缝」改成「弯荚 + 三粒轴向排布的籽」（荚的特征是籽沿轴向排，叶脉才向两侧分叉）。详见 [D38](docs/DECISIONS.md)。

线宽用 viewBox 单位 `.7` 而不是 `non-scaling-stroke`：后者把线钉死在 1.5px，图形一放大线就变细发飘，那正是「廉价感」的来源。三档尺寸 88 / 48 / 44px 是按盘心圆内弦长配的，不是随手调的。

中圈是**一整圈等分弧段**，不是方格、也不是三格弧窗：有几项、停在第几项、往两边各还有什么，一眼全在，点哪段就是哪段，没有"转到才算选中"的中间态。为什么用弧段而不是方格——方格是贴上去的，弧段是从这块盘上切下来的，同一圆心、同一线宽、同一留白，读起来是同一个物件。

弧段嵌在一圈**凹槽**里：槽比弧带每侧宽 2.4 单位，段间留 3.4° 的缝。没有凹槽时，七段白弧与白盘心并成一块，中圈读成"一个白环 + 几道辐条"（截图确认）；有了槽，缝里与上下两侧露出的都是槽底（`#97a3c1`，与白瓦 3.0:1），才读得出"一片片嵌进槽里"。弧带内径 118、外径 152（480 视框）：内径离盘心 7.6 单位，贴太近会糊成一块白饼；外径离家族环内沿 6 单位。

两层之间的切换是一段**有去有回**的编排，不是瞬间换图：

| 时刻 | 元素 | 动作 |
|---|---|---|
| 进·0ms | 6 个家族文字 | 缩小到 .90 + 反向旋转 +3° + 淡出，按 `i × 26ms` 错峰，240ms |
| 进·0ms | 大圈扇区 | 整圈同时缩到 .96 淡出（**delay 必须 0**：`both` 会把延迟期间钉在全亮，就是"滞后边框"）|
| 进·0ms | 中圈容器 | 整条弧带 `scale .40 → 1.49 → 1.43`（放大到占住大圈位置，带回落过冲），460ms |
| 进·100ms | 7 段弧 | 从 `rotate(−2°)` 回正并淡入，按 `i × 28ms`，300ms |
| 回·0ms | 中圈容器 | 先轻顶 1.46 再收到 .44 淡出，300ms |
| 回·100ms | 7 段弧 | 反序收（n−1−i），200ms |
| 回·180ms | 大圈扇区 | 从 `.80` 推出 + 中段过冲 1.03，按 `i × 20ms`，340ms |
| 回·240ms | 6 个家族文字 | 从 .88 推到 1 并淡入，按 `i × 20ms`，320ms |

退场不是 `innerHTML = ''` 一行抹掉——那会让 DOM 里没有节点可播动画。现在先挂 `.is-exit`，420ms 后再清。两类动画类（`is-lifting` / `is-returning`）只在"层数真的变了"时挂、780ms 后摘掉；`paint()` 由 hover 高频调用，写成"每次重绘都重播"就等于每划过一块扇区整盘闪一次。

**大圈退到 0 而不是幽灵态**：D40 试过 `.30`，实测把六族色相一起抹掉——六块填充的 L* 极差从 7.98 掉到 5.14，环向 L* 跳变数从 61 掉到 19，六块退成同一种冷灰，只剩描边可分。"明确的消失"用半透明做不到：既不像消失，又毁掉可辨性。现在展开态 `opacity: 0`，`pointer-events` 保持 `auto`，悬停 / 键盘聚焦 / 盘心正在讲的那块浮回 `1` —— **消失与可点是两件独立的事**。

两个实现陷阱都在实测里踩到：`fanVanish … both` 会把 opacity 钉在终帧 0，普通 `opacity: 1` 压不过 animation，hover 只升到 `.55`，必须显式 `animation: none`；`_wheel6.css` 还留着一条 v6 的 `.is-hot:not(.is-on) { opacity: .55 }` 半亮档，要写同档特异度的 `:not()` 版本才压得住。

中圈放大必须在**容器**上做（`ringGrow`），逐段各自动 scale 会各绕自己的包围盒，七段互相穿插成七块错位的瓦。容器是 HTML 不是 SVG，`transform-origin` 用 `50% 50%`：`transform-box: view-box` 在无 SVG 布局框的元素上等价 `border-box`，那时 240px 相对左上角，520px 控件会让整条弧带放大过程中偏左上 20px。

**按下态用显式类，不用 `:active`**：`:active` 只在真实指针按住时成立，键盘 Enter、脚本触发、触屏滑动取消三种情况全漏。`.is-pressing` 由 `pointerdown` 挂，由 `pointerup` / `pointercancel` / `pointerleave` / 全局 `pointerup` / `blur` / 确认入口六处摘。缩到 .93（−7.1%，1x 下 4.4px）并把描边从 1px 收到 1.6px —— 只改亮度在浅底上感知度太低，边界的位移才读得出"按下去"。

确认的强调是绕盘心的整段缩放 `1 → 1.032 → 1`，不是 `drop-shadow` 脉冲：后者在 520px 盘上肉眼不可见（v15 实测过）。

返回按钮则把大类一起清掉、回到闭合盘——**这是两个不同级别的返回**：点扇区是同级换类（保留已选大类、只清小类），点「← 重选大类」是降一层（连大类一起清）。

窄屏三层是**算术放不下**，不是调参问题。390 视口盘 342px（480 单位 = 0.7125px）：盘心 46% 半径 78.7px，中圈标签在 130 单位 = 92.6px 的环上、四字 14px 宽 56px → 内沿 64.6px，比盘心半径还靠里 14px。盘心任何落在中线附近、宽过半 65px 的字必然相交（实测四字主词与「古龙水型」叠 34–141 px²）。穷举过的方案全不成立：两圈都收到 12px 还差 1px 且破 `test-contrast` 下限；中圈外移到 148–156 单位会与家族标签挤到 490px² 且 7 段时相邻自撞；盘心放到 54% 盖住整条弧带。

定稿：**窄屏展开态让家族标签退场**，整条外带让给中圈标签（130 → 152 单位 = 108.3px，内沿 84.3px 越过盘心 5.6px）。配套把家族扇区命中区一起 `pointer-events: none` —— 留着就是"看不见却能点"的盲区，误触就换了大类。碰撞判据也从"几何相交"改成"只量真的看得见的元素"（逐级查 `visibility` / `display` / `opacity ≥ .05`），否则退场后的标签几何上还在，会被算成相交。

桌面 1440/1366 仍是两行标签并置：家族 193、小类 135（弧带中线），两行盒高 26px，字形框交叠 0。判据始终用 `Range` 量**字形外框**而不是按钮盒——padding 会把盒子撑得比字宽得多，按盒子判会把真重叠读成"还差 3px"。

缩小后的盘**在桌面端仍然可以直接点**：六块扇区展开态 `opacity 0`，悬停 / 键盘聚焦抬到 `1`，盘心 kick 从「已选定大类」变成**「点一下换到」**并给出那一类的名字——还没松手就知道点下去会发生什么。**窄屏例外**：342px 的盘上三层排不下（见下），家族标签与扇区命中区一起关掉，换大类走左上角「← 重选大类」。

确认只由**左键点击**决定，悬停不改任何状态：指针划过某段只让那段描边加深（`.is-hot`），盘心主词、`is-picked`、`selSub` 全都不动。原来 `focusSub = hovSub || sub` 会让指针划过就换盘心文字——`paint()` 是 hover 高频调用的，那等于文字跟着指针抖。

返回入口**不在盘心**：原本「换一个大类」是盘心底部一枚下划线小字，和「就选「X」，下一步」一上一下并排放在盘心中央，两个方向相反的动作挨着，拇指在触屏上够错一个就反了。现在移到控件左上角一枚 44px 高的胶囊「← 重选大类」，有 `:hover` / `:active`（下沉 1px）/ `:focus-visible` 三态。

所有渲染文案**不用句末句号**，句中照旧保留——句号断开的是两件事（做什么 / 怎么做），删了会黏成一长句。

窄屏（≤620px）盘心还多一颗虚线胶囊「中圈可不选」——原来只有桌面端盘心那颗「直接下一步」在说这件事，而它在窄屏是隐藏的，**最需要这句话的人恰好看不到**。

在精确指针设备上圆盘还可以拖着转（阈值 2.2°，低于它算点击），松手走惯性衰减后吸附到最近扇区；触屏不启用——手机圆盘占首屏大半，一刀切 `touch-action: none` 会让用户在圆盘上滑不动页面。

出结果：3 瓶具体香水，每瓶含

- 品牌 / 名称 / 浓度 / 源家族
- 前调、中调、后调完整列表 + 每个层次的通俗解释
- 2–3 条推荐理由，每条都能反推到上面某一题的答案
- 持香推断、适配季节、原始数据页面链接

## 怎么跑起来

**不需要 npm install，零依赖。**

```bash
# 方式一：用自带的静态服务器（推荐，双击 index.html 会被 CORS 拦）
node server.js
# → http://localhost:8080

# 方式二：你已有的任意静态服务器
python -m http.server 8080
npx serve .
```

> 为什么不能双击 `index.html`：浏览器在 `file://` 协议下会拦掉 `fetch('./data/*.json')`。这不是 bug，是安全策略。

## 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生 HTML / CSS / ES Module | 无构建步骤，改完刷新就生效。新手第一个项目不该被 webpack 卡住 |
| 打分 | 纯函数规则引擎（`src/scoring.js`） | 确定性、可测试、可解释。**不调用大模型** |
| 数据 | 两个 JSON 文件，前端直接 fetch | 千级条目按规则打分单次 8.8ms（实测），不值得上数据库 |
| 服务器 | `node:http` 内置模块 | 30 行，能看懂 |
| 测试 | 五个 Node 脚本，零测试框架 | 直接 `node scripts/xxx.mjs` 就能跑 |
| 视觉 | 手写 CSS，瑞士国际主义排版（白底 + 墨黑 + 单一朱红强调） | 层级只靠字号、字重、留白和一根 8px 墨线，不靠阴影、渐变、圆角。**零装饰是刻意的**：上两版试过深空 HUD 和宣纸纹，两者的"设计感"都来自贴图而不是结构 |

**为什么不用大模型做推荐**：模型给不出稳定结果——同一个问题问两次可能给两瓶不同的香，而且它无法保证"这瓶确实有佛手柑"。规则引擎的每一条理由都能复算，这是这个项目的立身之本。

## 推荐逻辑：怎么算出来的

分数由 8 个可独立验证的部分相加，满分 127：

| 因子 | 权重 | 说明 |
|---|---|---|
| 家族吻合（情绪 + 场合） | 52 | 用户偏好向量与这瓶的家族向量做点积 |
| **情绪锚点香调命中** | 22 | 每种情绪对应 5 个锚点香调（如"清冷"= 鸢尾/紫罗兰/柏树/香根草/焚香） |
| 浓度吻合 | 18 | 用琥珀 + 美食占比近似"厚重感"，与 1–5 偏好比对 |
| 喜欢的香调命中 | 14 | 用户点名的香调 |
| 季节吻合 | 10 | 可选 |
| 时段吻合 | 6 | 由场合推导（约会→夜晚） |
| 知名度微调 | 5 | 避免全推冷门怪香 |
| 讨厌的香调命中 | **−40** | 强惩罚，几乎直接出局 |

**为什么要"情绪锚点"这一层**：只用家族会翻车。实测发现"清冷 + 约会"会把 Creed Aventus 排第一——它在源站被标成以花香为主的 Orchard Fruit，家族层面看着没问题，但"清冷"要的是鸢尾那种冷感。加了锚点香调层之后，第一位变成 Byredo Gypsy Water（含鸢尾 + 焚香），才符合语义。

排名还做**源家族 + 品牌双重去重**：前三名既不会全是同一个源家族，也不会全是同一个牌子。只按家族去重拦不住 Byredo——它有 9 瓶、横跨 4 个家族，实测点选"佛手柑"时会三席全是 Byredo（见 `docs/DECISIONS.md` D09）。

## 已知局限（诚实清单）

这些不是待办，是**当前版本确实做不到**的事：

1. **不含价格与购买渠道** —— 数据源没有这个字段，我们也不编
2. **持香与扩散是按浓度推断，非实测** —— 页面标注"推断"，24 瓶因源站未标浓度而显示"未标注"
3. **库容受限于上游** —— 当前 1228 瓶（Scento 开放数据集全量合格条目），你心里已经有的那瓶仍可能不在库里
4. **家族映射是人工表** —— 源站的 14 个家族名字与面向用户的 6 大分类不同名，中间靠 `sourceFamilyMap` 手工映射，有主观成分
5. **没有用户账户、不保存历史** —— 每次刷新从头开始
6. **规则权重是手工调的** —— 没有真实用户数据做拟合

## 测试

```bash
node scripts/test-scoring.mjs      # 106 项：全组合出结果、幂等、讨厌香调生效、品牌+家族双重多样性、单调性
node scripts/test-render.mjs       # 207 项：七步流程走通、圆盘 6/5 扇区与 radiogroup 语义、扇形本体可点、盘心三态与标本线稿、盘心圆弧约束、两栏互斥、每类标识不撞形、一圈等分弧段与进出场动画、返回路径（清空 vs 切换）、结果页三调与理由齐全、无 NaN
node scripts/test-contrast.mjs     # 38 项：文字对比度 ≥4.5、控件边界 ≥3、字号 ≥12px、焦点环、触控目标 ≥44px
node scripts/qa-data.mjs           # 数据体检：结构、唯一性、权重、家族覆盖、可溯源 + 5 项合规断言
node scripts/test-compliance.mjs   # 10 项：证明上面那些断言真的会失败
```

五套全绿才允许提交。

### 为什么有第五套（test-compliance）

前四套都是"验证事情是对的"。第五套验证的是**"验证本身有效"** —— 它往内存里的数据副本注入 9 种违规（塞 description、删 attribution、清空三调、改上游行数、造 id 重复、单一品牌垄断……），确认 `qa-data` 的每条断言都能真的报错。

一个从不失败的测试等于没有测试。这套跑完还会用未篡改的基线再跑一遍，确认断言没有**假阳性**（没病说有病）。

`test-contrast.mjs` 里的触控断言同样配了变异测试：删掉 `.chip` 的 `min-height: 44px` 会立刻报 `香调标签(.chip) = 未声明px < 44px`。

**注意它不写盘**：全程在内存副本上操作。第一版试过用子进程 + 临时改文件，在本机沙箱下 `stdio:'pipe'` 被拒、拿不到子进程输出，测试变成静默失败 —— 差点以为断言是好的。

### `test-render.mjs` 与真机视觉核查的分工

DOM 桩证明逻辑与文案正确，不证明渲染尺寸。渲染层面的核查用的是**本机 Edge 无头模式**（puppeteer 自带的 Chromium 被沙箱拦，直接 `spawnSync` 调 msedge.exe 可行）：自动点完四步、在 1280/768/390 三档视口下逐元素量 `getBoundingClientRect`，实测修掉了三个问题——滑块命中区只有 2px、`.chip` 39px、`.btn` 37px。核查命令见 `docs/DEPLOY.md`。

**静态截图仍覆盖不到的**：hover/focus 的真实观感、触屏手感、iOS Safari 上的字体渲染。这三项需要你人工过一遍。
