# 零基础香水选择器

**用四个问题，从一个完全不懂香水的人，走到具体某瓶香水的名字。**

不是"猜你喜欢"的黑盒推荐。每一瓶都给你完整的前调 / 中调 / 后调，以及**能反推回你刚才某个答案**的推荐理由。

---

## 它解决什么问题

新手买香水最常踩的坑，不是"买不到好香水"，而是**顺序错了**：

1. 先看别人推荐的具体香名 → 买了发现自己晕白花 / 讨厌甜 / 受不了皮革
2. 不知道香水按家族分，只看"好闻"两个字，实际无从判断
3. 前中后调看不懂，以为香水是"一个味道"

所以这个工具的顺序是反的：

```
先定大方向（家族）→ 再缩范围（场合 + 浓度 + 香调）→ 最后给具体香名 + 三调 + 理由
```

---

## 核心用户流程

前两步是**环形圆盘**（仪表盘交互），后两步是滑杆与香调标签。

| 步 | 问题 | 为什么这么问 |
|---|---|---|
| 1 | 你想被别人闻成什么感觉？（清冷 / 温暖 / 干净 / 神秘 / 明亮 / 慵懒） | 绕过"香调术语"，直接问感受。新手唯一真正能回答的问题 |
| 2 | 主要在哪里用？（上班上课 / 约会 / 日常居家 / 正式场合 / 运动户外） | 同一瓶香在办公室和约会里表现完全不同，场合决定了扩散与浓度的上限 |
| 3 | 希望它有多浓？（1–5 滑块） | 把抽象的"浓度"翻译成"多远能闻到、能留多久" |
| 4 | 有没有喜欢 / 受不了的味道？（可跳过，56 个香调） | **点名"讨厌"比点名"喜欢"更有用** —— 排除比加分更准 |

圆盘不是纯 SVG：扇形用 SVG 画，可点区域是盖在上面的真实 `<button>`，所以触控目标 >= 44px、键盘 Tab 进得去、方向键能在扇区间漫游。

盘心是这个控件唯一显示状态的地方，三态各有不同体积：**空态**浅底、**悬停**提亮一档并加四角角标、**已选定**整块压成实心墨、文字反白。压墨不是装饰——215px 的浅色方块压不住 504px 的圆盘，体量对不上时读起来像一张便签。盘心取内接正方形（内弧半径 × √2 = 42.7%），四角正好顶到内弧，方与圆互相咬合。

在精确指针设备上圆盘还可以拖着转（阈值 2.2°，低于它算点击），松手走惯性衰减后吸附到最近扇区；触屏不启用——手机圆盘占首屏大半，一刀切 `touch-action: none` 会让用户在圆盘上滑不动页面。

出结果：3 瓶具体香水，每瓶含

- 品牌 / 名称 / 浓度 / 源家族
- 前调、中调、后调完整列表 + 每个层次的通俗解释
- 2–3 条推荐理由，每条都能反推到上面某一题的答案
- 持香推断、适配季节、原始数据页面链接

## 怎么跑起来

**不需要 npm install，零依赖。**

```bash
# 方式一：用自带的静态服务器（推荐，双击 index.html 会被 CORS 拦）
node server.js
# → http://localhost:8080

# 方式二：你已有的任意静态服务器
python -m http.server 8080
npx serve .
```

> 为什么不能双击 `index.html`：浏览器在 `file://` 协议下会拦掉 `fetch('./data/*.json')`。这不是 bug，是安全策略。

## 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生 HTML / CSS / ES Module | 无构建步骤，改完刷新就生效。新手第一个项目不该被 webpack 卡住 |
| 打分 | 纯函数规则引擎（`src/scoring.js`） | 确定性、可测试、可解释。**不调用大模型** |
| 数据 | 两个 JSON 文件，前端直接 fetch | 400 瓶的量级不值得上数据库 |
| 服务器 | `node:http` 内置模块 | 30 行，能看懂 |
| 测试 | 五个 Node 脚本，零测试框架 | 直接 `node scripts/xxx.mjs` 就能跑 |
| 视觉 | 手写 CSS，瑞士国际主义排版（白底 + 墨黑 + 单一朱红强调） | 层级只靠字号、字重、留白和一根 8px 墨线，不靠阴影、渐变、圆角。**零装饰是刻意的**：上两版试过深空 HUD 和宣纸纹，两者的"设计感"都来自贴图而不是结构 |

**为什么不用大模型做推荐**：模型给不出稳定结果——同一个问题问两次可能给两瓶不同的香，而且它无法保证"这瓶确实有佛手柑"。规则引擎的每一条理由都能复算，这是这个项目的立身之本。

## 推荐逻辑：怎么算出来的

分数由 8 个可独立验证的部分相加，满分 127：

| 因子 | 权重 | 说明 |
|---|---|---|
| 家族吻合（情绪 + 场合） | 52 | 用户偏好向量与这瓶的家族向量做点积 |
| **情绪锚点香调命中** | 22 | 每种情绪对应 5 个锚点香调（如"清冷"= 鸢尾/紫罗兰/柏树/香根草/焚香） |
| 浓度吻合 | 18 | 用琥珀 + 美食占比近似"厚重感"，与 1–5 偏好比对 |
| 喜欢的香调命中 | 14 | 用户点名的香调 |
| 季节吻合 | 10 | 可选 |
| 时段吻合 | 6 | 由场合推导（约会→夜晚） |
| 知名度微调 | 5 | 避免全推冷门怪香 |
| 讨厌的香调命中 | **−40** | 强惩罚，几乎直接出局 |

**为什么要"情绪锚点"这一层**：只用家族会翻车。实测发现"清冷 + 约会"会把 Creed Aventus 排第一——它在源站被标成以花香为主的 Orchard Fruit，家族层面看着没问题，但"清冷"要的是鸢尾那种冷感。加了锚点香调层之后，第一位变成 Byredo Gypsy Water（含鸢尾 + 焚香），才符合语义。

排名还做**源家族 + 品牌双重去重**：前三名既不会全是同一个源家族，也不会全是同一个牌子。只按家族去重拦不住 Byredo——它有 9 瓶、横跨 4 个家族，实测点选"佛手柑"时会三席全是 Byredo（见 `docs/DECISIONS.md` D09）。

```bash
# 1. 从上游下载最新 perfumes.jsonl
curl -L -o data/source/perfumes.upstream.jsonl \
  https://raw.githubusercontent.com/Scento-com/perfume-dataset/main/perfumes.jsonl

# 2. 重跑管线（纯本地，不联网）

# 3. 体检
node scripts/qa-data.mjs
```

## 已知局限（诚实清单）

这些不是待办，是**当前版本确实做不到**的事：

1. **不含价格与购买渠道** —— 数据源没有这个字段，我们也不编
2. **持香与扩散是按浓度推断，非实测** —— 页面标注"推断"，24 瓶因源站未标浓度而显示"未标注"
3. **只有 400 瓶** —— 你心里已经有的那瓶大概率不在库里
4. **家族映射是人工表** —— 源站的 14 个家族名字与面向用户的 6 大分类不同名，中间靠 `sourceFamilyMap` 手工映射，有主观成分
5. **没有用户账户、不保存历史** —— 每次刷新从头开始
6. **规则权重是手工调的** —— 没有真实用户数据做拟合

## 测试

```bash
node scripts/test-scoring.mjs      # 106 项：全组合出结果、幂等、讨厌香调生效、品牌+家族双重多样性、单调性
node scripts/test-render.mjs       # 47 项：四步流程走通、圆盘 6/5 扇区与 radiogroup 语义、扇形本体可点、盘心内接正方形、两栏互斥、结果页三调与理由齐全、无 NaN
node scripts/test-contrast.mjs     # 28 项：文字对比度 ≥4.5、控件边界 ≥3、字号 ≥12px、焦点环、触控目标 ≥44px
node scripts/qa-data.mjs           # 数据体检：结构、唯一性、权重、家族覆盖、可溯源 + 5 项合规断言
node scripts/test-compliance.mjs   # 10 项：证明上面那些断言真的会失败
```

五套全绿才允许提交。

### 为什么有第五套（test-compliance）

前四套都是"验证事情是对的"。第五套验证的是**"验证本身有效"** —— 它往内存里的数据副本注入 9 种违规（塞 description、删 attribution、清空三调、改上游行数、造 id 重复、单一品牌垄断……），确认 `qa-data` 的每条断言都能真的报错。

一个从不失败的测试等于没有测试。这套跑完还会用未篡改的基线再跑一遍，确认断言没有**假阳性**（没病说有病）。

`test-contrast.mjs` 里的触控断言同样配了变异测试：删掉 `.chip` 的 `min-height: 44px` 会立刻报 `香调标签(.chip) = 未声明px < 44px`。

**注意它不写盘**：全程在内存副本上操作。第一版试过用子进程 + 临时改文件，在本机沙箱下 `stdio:'pipe'` 被拒、拿不到子进程输出，测试变成静默失败 —— 差点以为断言是好的。

### `test-render.mjs` 与真机视觉核查的分工

DOM 桩证明逻辑与文案正确，不证明渲染尺寸。渲染层面的核查用的是**本机 Edge 无头模式**（puppeteer 自带的 Chromium 被沙箱拦，直接 `spawnSync` 调 msedge.exe 可行）：自动点完四步、在 1280/768/390 三档视口下逐元素量 `getBoundingClientRect`，实测修掉了三个问题——滑块命中区只有 2px、`.chip` 39px、`.btn` 37px。核查命令见 `docs/DEPLOY.md`。

**静态截图仍覆盖不到的**：hover/focus 的真实观感、触屏手感、iOS Safari 上的字体渲染。这三项需要你人工过一遍。
